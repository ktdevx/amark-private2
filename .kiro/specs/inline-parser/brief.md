# Brief: inline-parser

## Problem
ブロック構造が確定した後、段落や見出しの中身を、強調、リンク、コードスパン、オートリンク、生の HTML などのインライン要素として解析する必要がある。CommonMark の区切り文字のアルゴリズム（delimiter run と process emphasis）や、リンクとブラケットの処理は複雑である。拡張（新しい区切り文字や、きっかけの文字がないインライン構文）が同じ仕組みに乗れるよう、エンジンとして汎用化しなければならない。また、Amark が CommonMark に完全準拠し、拡張の組み合わせで GFM 相当を表現できることを、最終的に検証する場所も必要である。

## Current State
まだ存在しない。`block-parser` が定義するインラインへの委譲のインタフェースと、リンク参照定義の表を使う。

## Desired Outcome
- インライン構文エンジンと公開インライン構文 API がある。この API で次のものを定義できる。
  - きっかけの文字に反応する構文
  - きっかけの文字がない構文（拡張オートリンク相当）
  - 区切り文字の種類（`*`、`_` に加えて、拡張で `~` なども登録できる）とその規則
  - ブラケットの後処理（リンク、画像、脚注参照）
- CommonMark の全インライン構文を、組み込み拡張として実装する。
  - 全インライン構文：バックスラッシュのエスケープ、文字参照、コードスパン、強調、リンク、画像、オートリンク、生の HTML、ハードブレーク、ソフトブレーク、テキスト
- インラインの構文トークンを記録する。記録するのは、エスケープや文字参照の元の表記、区切り文字の実際の文字と長さ、リンクの書式（インライン、完全参照、省略参照、ショートカット参照）、空白などである。
- **CommonMark spec の準拠テスト**：spec.txt の全例を Naos のテストとして実行し、HTML 出力で 100% パスする。
- **拡張 API の表現力の検証**：GFM 相当のフックを使う小さな拡張を、テストの中にだけ置く。これらを組み合わせて、それぞれが期待どおり動くことを確かめる。
  - 表、取り消し線、タスクリスト、拡張オートリンク、タグフィルタ、脚注
  - 配布するライブラリには含めない。
- インラインのファジングターゲットと、病的な入力（深い入れ子、大量の区切り文字）に対する計算量のテストがある。

## Approach
- 区切り文字のスタックとブラケットのスタックを汎用化する。区切り文字の種類ごとの規則（開く/閉じるの判定、長さの一致規則、生成するノード）を拡張から登録できるようにする。
- 組み込みの構文も公開 API だけを使って実装し、内部専用の近道を作らない。
- 準拠テストは、spec.txt から例を取り出してテストを生成する。生成はビルド時でも事前でもよい。spec.txt のバージョンは固定する。

## Scope
- **In**：
  - インライン構文エンジンと公開インライン構文 API
  - CommonMark の全インライン構文
  - インラインの構文トークンの記録
  - CommonMark spec の準拠テスト一式
  - テスト専用の検証用拡張（GFM 相当）
  - インラインのファジング
- **Out**：
  - GFM の配布、GFM spec の公式準拠の主張
  - Markdown への書き戻し

## Boundary Candidates
- インライン構文エンジン
- CommonMark のインライン構文の定義（組み込み拡張）
- 準拠テストと拡張 API の表現力の検証（プロジェクト全体の受け入れゲート）

## Out of Boundary
- ブロック構造の解析
- HTML 出力の規則（`html-renderer`）。ただし、準拠テストの中で HTML 出力の不具合が見つかったら、`html-renderer` に戻って直す。

## Upstream / Downstream
- **Upstream**：`block-parser`（委譲のインタフェース、リンク参照定義の表）、`html-renderer`（準拠テストで使う）
- **Downstream**：`markdown-renderer`、利用者の拡張

## Existing Spec Touchpoints
- **Extends**：`syntax-tree` の拡張記述子に、インライン構文のスロットを足す。検証用拡張の実装で、`block-parser` や `html-renderer` の拡張 API に不足が見つかったら、それぞれの spec に戻って補う。
- **Adjacent**：`block-parser`、`html-renderer`

## Constraints
- CommonMark spec（固定したバージョン）の例に 100% パスすることを必須にする。
- spec.txt のライセンスは CC-BY-SA 4.0 なので、テストデータとしてだけ扱い、配布するライブラリには含めない。
