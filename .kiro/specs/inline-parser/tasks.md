# Implementation Plan

> 前提：`block-parser`（`parser.h`、`scan.h`、`block.h`、`commonmark.h`、`src/parse/inline_stage.c`、`src/syntax/commonmark.c`、`tests/support/gen_spec_examples.cmake`、`amark_test_parse`、`amark_test_parse_gfm`、`bench/` と `amark_add_bench`）と `html-renderer`（`render.h`、`html.h`、`amark.core.html`、`amark_test_html_gfm`）の実装が済んでいること。どちらかがない間は、このタスクを始めない。

- [ ] 1. 基盤：公開ヘッダ、純粋な関数、文字の宣言
- [ ] 1.1 インラインの公開ヘッダと、ビルドとヘッダの検査への配線を用意する
  - design の InlineApi のとおりに、委譲先、文脈の関数、6 つのスロットの構造体、結果と flanking と規則の列挙、純粋な関数、文字の集合、役割の番号を宣言する
  - 内部の構造体のヘッダと、エンジンの空の実装（委譲先は中身が空なら何もせず、それ以外は未実装の誤りを返す）をライブラリのソースに足す
  - 全体のヘッダの 4 番目の組の `block.h` と `commonmark.h` の間に含め、C++ の取り込みのテストから各関数を呼ぶ
  - `tests/inline` のディレクトリと、その CMake の枠（`amark_add_test` で単体テストを足せる形）を作り、`tests` から追加する
  - 公開ヘッダの検査（単独のコンパイル、正規の順、エクスポートの検査）がすべて通り、ライブラリが静的と動的の両方でビルドできる
  - _Requirements: 8.8_

- [ ] 1.2 区切り文字の開閉の判定と照合を、パースの文脈なしの関数として実装する
  - CommonMark 0.31.2 の左右の flanking（Unicode の空白と句読点、中身の端）と、`*` 型と `_` 型の開閉の規則を実装する
  - 3 の倍数の規則、使う長さ、下限の表を持つ照合を、配列の上の関数として実装し、EXACT の規則（同じ文字の最も近い開き、長さの一致）を含める。エンジンが後で同じ内部の関数を使えるように分けて置く
  - `capacity` の不足と小さい `struct_size` を不正な引数にする
  - delimiter のテストが、flanking の表の全組み合わせ、spec の強調の章の代表の並びの照合、EXACT、`capacity` の境界を確かめて通る
  - 1.3 と 1.4 と同じ `tests/inline` の CMake にテストを足すので、並行にしない
  - _Boundary: InlineDelimiters_
  - _Requirements: 5.8_

- [ ] 1.3 生の HTML の判定の関数を実装する
  - 開始タグと終了タグは `block-parser` の走査の関数を使い、コメント（0.31.2 の `<!-->` と `<!--->`）、処理命令、宣言、CDATA を判定し、終わりの位置を返す
  - 改行を LF として扱い、長さで境界を確かめ、NUL を終端として扱わない
  - raw HTML のテストが、各構文の成立と不成立、属性の改行、閉じない入力で通る
  - _Boundary: InlineScanHtml_
  - _Requirements: 7.8_

- [ ] 1.4 エスケープに関わる文字の宣言と、その問い合わせを実装する
  - 凍結した構文セットのスロットから、宣言の文字、印字可能なきっかけの文字、区切り文字、ブラケットの文字（画像を扱うなら `!`）を集める
  - 拡張を指定した問い合わせはその拡張のスロットだけから作り、凍結していない構文セットは状態の誤りにする
  - special chars のテストが、テストの中の拡張で、宣言、自動の追加、拡張ごとの問い合わせ、誤りを確かめて通る
  - _Boundary: InlineChars_
  - _Requirements: 9.1, 9.2, 9.3_

- [ ] 2. インライン構文エンジン
- [ ] 2.1 項目の並びと、構造の組み立てとトークンの記録（反映）を実装する
  - テキストの単位の並び、区切り文字の並び、ブラケットの開き、ノードの項目、子の並びを持つ項目の木と、預かったトークンの配列を作る
  - 直前の通常のテキストに足し、隣り合う TEXT の単位を 1 つにし、残りのテキストを隣と 1 つにしないまとめ方を実装する
  - 反映を、後順の明示のスタックで部分木を下から組み、最上位を葉に付け、ノードごとにトークンを中身の順に記録し、残りのテキストの literal を記録する順で実装する。使われなかったノードを先に解放する
  - INTERNAL の単体テストが、手で作った項目の並び（入れ子 10 万段を含む）を段落に反映し、ロスレス性の検証と元の表記の判定に通り、スタックを使い果たさないことを確かめる
  - _Requirements: 2.2, 8.1, 8.2, 8.10, 11.2_

- [ ] 2.2 エンジンの入口、準備、走査を実装する
  - 葉の検査、スロットの列挙と検査、優先度での安定な並べ替え、文字ごとの構文の表、葉ごとの状態の 0 埋めの確保を実装する
  - 中身の先頭と末尾の空白を葉の SPACE、TAB_REMAINDER、LINE_BREAK のトークンにし、その間だけを走査する
  - 位置ごとに、置き換えとタブの残りの単位、構文の試行、テキストの範囲の前進、どの構文も消費しない改行のソフトブレークを処理する。配置済みと自由な中身を同じ規則で扱い、グローバルな状態を持たない
  - エンジンの API のテストが、インライン構文のない構文セットで、テキストとソフトブレークの木、先頭と末尾の空白、NUL と不正な UTF-8 の REPLACED、タブの残りのトークン、優先度と構文セットの順、スロットの検査の誤りを確かめて通る
  - _Requirements: 1.3, 1.4, 1.7, 2.1, 2.2, 2.4, 2.5, 2.7, 3.1_

- [ ] 2.3 拡張に渡す文脈の関数と、誤用の検出を実装する
  - 問い合わせ（パースの文脈、葉、中身、解析の範囲、前後の符号位置、葉ごとの状態）と、ノードの作成、トークンの預かり、出す、テキストとして出す、テキストとして飛ばす、直前の空白の取り込みを実装する
  - 出した範囲が預けたトークンでちょうど覆われるかを確かめ、出し方の矛盾、範囲の越え、呼び出しの外の使用を状態の誤りにする
  - コールバックのエラーとトークンの記録の検査の誤りを、解析の結果としてそのまま返す
  - エンジンの API のテストが、テストの中の構文で各関数の契約、6 つの誤用、失敗の伝播（パースが止まりリークしない）を確かめて通る
  - _Requirements: 1.6, 2.6, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7, 8.9, 14.2_

- [ ] 2.4 区切り文字の種類と、区切り文字のスタックの処理を実装する
  - 走査で同じ文字の並びを求め、flanking と長さの範囲で積むかテキストにするかを決める
  - 1.2 の内部の関数で、下限の表を使う区切り文字の処理を実装し、一致で `make` のノードに間の項目を移し、使った文字を 1 文字ずつの DELIMITER（OPEN と CLOSE）として預ける
  - 残った文字を残りのテキストの項目にし、同じ文字の種類が複数あるときは構文セットの後のものを使う
  - エンジンの API のテストが、テストの中の区切り文字（新しい文字、EMPHASIS と EXACT、長さの範囲、異なる文字）で、木、トークンの役割、残りの literal を確かめ、照合の関数と同じ結果になることを確かめて通る
  - _Depends: 1.2_
  - _Requirements: 5.1, 5.2, 5.3, 5.4, 5.5, 5.6, 14.2_

- [ ] 2.5 ブラケットのスタックと後処理を実装する
  - `[` と `![` の開き、`bracket_after`、閉じでの後処理の優先度の順の試行、無効の開き、成立しないときの残りのテキストを実装する
  - 包む（中の区切り文字を先に処理して子にする）と置き換える（中の項目とノードとトークンを捨てる）を実装し、どちらも開きのトークンをエンジンが預ける
  - LINK の性質のノードで、前の `[` の開きを、すでに無効のものに着くまで無効にする
  - エンジンの API のテストが、テストの中のブラケットの後処理で、包む、置き換える、無効化、成立しない開きと閉じ、画像の開きを確かめて通る
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 14.2_

- [ ] 2.6 きっかけの文字を持たない構文（テキストの走査）を実装する
  - 区切り文字とブラケットの処理の後、通常のテキストの項目の TEXT の単位だけが続く最大の範囲を、テキストの走査のスロットに優先度の順に渡す
  - 示した範囲をノードの項目に置き換えてテキストを分け、ノードのトークンが範囲をちょうど覆うかを確かめ、続きを試し直す。リンクの中かを祖先の項目の性質で答える
  - エンジンの API のテストが、テストの中の走査で、強調の中のテキスト、エスケープと文字参照で区切られる範囲、残りのテキストを渡さないこと、リンクの中の判定、被覆を確かめて通る
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 14.2_

- [ ] 3. テストの補助、既定の委譲先、組み込みの拡張の枠
- [ ] 3.1 インラインの検査の補助と、生成テストの登録を用意する
  - 委譲先に `amark_inline_parse` を明示して `amark_test_parse_check` を呼ぶパースの補助と、ダンプと HTML を照合する 2 つの検査の関数（オプションの語 values、layout、spelling、style、html、gfm、noeol、crlf、cr）を実装する
  - `tests/inline` の CMake で、補助のライブラリ（Naos、INTERNAL）と、`gen_spec_examples.cmake` の `CHECK=` によるデータのテストの登録を用意する
  - text のケース（テキストのまとめ、先頭と末尾の空白、NUL と不正な UTF-8、タブの残り、改行の種類）が、木の不変条件、ロスレス性、根の元の表記の判定、逐次の入力の一致とともに通る
  - _Requirements: 1.5, 8.2, 11.4, 12.2, 14.1, 14.4_

- [ ] 3.2 既定の委譲先をこのエンジンにする
  - `block-parser` の既定の委譲先を選ぶ 1 か所が `amark_inline_parse` を返すようにする
  - 委譲先を指定しないパースでエンジンが使われ、単純な委譲先を明示すれば従来どおりの木になることを、テストで確かめて通る。`block-parser` の既存のテストがすべて通る
  - _Requirements: 1.1, 1.2_

- [ ] 3.3 CommonMark のインライン構文の 8 つの拡張の枠を、構文セットの構築に足す
  - `src/syntax` の共有の内部ヘッダと、8 つの構文のファイルの拡張の記述子（名前とスロットの表。中身は後のタスクで埋める）を作る
  - CommonMark の構文セットの構築関数の表のブロック構文の後に 8 つを足し、拡張の取得の関数が 18 の拡張を返すようにする。`block-parser` の構文セットのテストが数と順を数えていれば、その期待値にインラインの分を加える
  - 構築した構文セットが凍結でき、8 つの拡張を名前で引け、既存のパースのテストがすべて通る
  - _Requirements: 7.2, 7.3_

- [ ] 4. CommonMark のインライン構文
- [ ] 4.1 (P) バックスラッシュのエスケープと文字参照を実装する
  - ASCII の句読点のエスケープを ESCAPE のテキストに、`\` と改行をハードブレーク（MARKER と LINE_BREAK と後の空白、形 backslash）にする
  - `amark_char_ref_decode` で解読できる参照を CHAR_REF のテキストにし、成立しない `\` と `&` をテキストのままにする
  - escape と char_ref のケースが、トークン、literal の値、style、spec の該当する節の例で通る
  - _Boundary: CommonMarkInline（backslash_escape、char_ref）_
  - _Requirements: 7.1, 7.4, 7.6, 8.3, 8.4, 8.7, 14.1_

- [ ] 4.2 (P) コードスパンを実装する
  - バッククォートの列の長さで閉じを探し、なければ列の全体をテキストとして飛ばす。葉ごとの状態に長さごとの最後の位置を持ち、閉じのない長さを二度探さない
  - 中の単位を literal のトークンにし、詰め物の両端の 1 バイトを PADDING にし、backticks と padded を記録する
  - code_span のケースが、改行の空白への折り返し、詰め物の規則、空白だけの中身、閉じない列、強調やリンクより強く結びつくことを確かめて通る
  - _Boundary: CommonMarkInline（code_span）_
  - _Requirements: 7.1, 7.4, 7.6, 7.7, 8.4, 8.5, 14.1_

- [ ] 4.3 (P) 強調と強い強調を実装する
  - `*`（ASTERISK）と `_`（UNDERSCORE）の区切り文字の種類を、EMPHASIS の規則と長さ 1 以上で登録する
  - 使う長さ 1 で emph、2 で strong を作り、区切り文字の style を記録する
  - emphasis のケースが、入れ子、一部だけを使う並び、残りの区切り文字の literal、`_` の語の中の規則、3 の倍数の規則を、トークンの役割とともに確かめて通る
  - _Boundary: CommonMarkInline（emphasis）_
  - _Requirements: 5.7, 7.1, 7.6, 8.4, 8.5, 14.1_

- [ ] 4.4 (P) インラインの形のリンクと画像を実装する
  - `]` の後の `(`、空白、宛先、空白、タイトル、空白、`)` を `block-parser` の走査の関数で読み、包んで link か image を作る
  - 記録の規約の表のとおりに、括弧、山括弧、引用符の DELIMITER と役割、宛先とタイトルの単位の項目、空白と改行を預け、form、angle、title_quote を記録する。葉ごとの状態に閉じない引用符の印を持つ
  - link の性質を宣言し、前の `[` の開きが無効になるようにする
  - link と image のケースが、エスケープと文字参照の宛先とタイトル、括弧の深さの上限、山括弧、複数行のタイトル、リンクの中のリンク、画像の中のリンクを確かめて通る
  - _Boundary: CommonMarkInline（link のインラインの形）_
  - _Requirements: 6.5, 7.1, 7.4, 7.6, 8.4, 8.5, 11.3, 14.1_

- [ ] 4.5 参照の形のリンクと画像を実装する
  - 完全参照のラベル、省略参照、ショートカットを、`bracket_after` と完全なラベルの優先の規則で判定する
  - リンクが持つラベルの値と同じ文字列で、パースの文脈の定義の検索を引き、見つからなければ成立しない
  - 完全参照はラベルのトークンを、省略参照とショートカットはラベルの値を記録し、form を記録し、宛先とタイトルを記録しない
  - link と image のケースが、大文字と小文字の違うラベル、同じラベルの定義、定義のない参照、NUL を含むラベル、解決した宛先とタイトルの値を確かめて通る
  - _Depends: 4.4_
  - _Boundary: CommonMarkInline（link の参照の形）_
  - _Requirements: 6.7, 7.1, 8.4, 8.5, 8.6, 14.1_

- [ ] 4.6 (P) オートリンクを実装する
  - `<` の後の URI とメールアドレスを 0.31.2 の規則で判定し、link（`<` と `>` の DELIMITER と役割）と、子の text（TEXT、CHAR_REF、REPLACED）を出す
  - 文字参照を解読し、メールアドレスに `mailto:` を足し、LF と CR を `%0A` と `%0D` にした宛先と、form autolink を記録する
  - autolink のケースが、スキームの長さの境界、エスケープが働かないこと、メールアドレス、生の HTML より先に試されることを確かめて通る
  - _Boundary: CommonMarkInline（autolink）_
  - _Requirements: 7.1, 7.5, 7.6, 7.7, 8.4, 8.5, 14.1_

- [ ] 4.7 (P) 生の HTML を実装する
  - 1.3 の判定の関数で html_inline を出し、中の単位を literal のトークンにする
  - 葉ごとの状態に、閉じない構文ごとの「この位置より後にない」の印を持ち、最後までの走査を繰り返さない
  - raw_html のケースが、各構文、複数行のタグ、改行のトークン、強調より強く結びつくことを確かめて通る
  - _Depends: 1.3_
  - _Boundary: CommonMarkInline（raw_html）_
  - _Requirements: 7.1, 7.4, 7.6, 7.7, 8.4, 14.1_

- [ ] 4.8 (P) ソフトブレークと空白のハードブレークを実装する
  - 改行で直前のテキストの末尾の空白を取り込み、改行の直前の 2 バイトが空白ならハードブレーク（形 spaces）、それ以外はソフトブレークにする
  - 改行の後の空白とタブも、そのノードの SPACE（TAB_REMAINDER）にする
  - line_break のケースが、末尾の空白とタブ、タブの残り、自由な中身の行頭の空白、段落の最後の行の空白を確かめて通る
  - _Boundary: CommonMarkInline（line_break）_
  - _Requirements: 7.1, 7.6, 8.5, 8.7, 10.2, 14.1_

- [ ] 5. 統合と準拠テスト
- [ ] 5.1 組み合わせのケースと、構文セットの組み替えを確かめる
  - 引用とリストの中の段落、遅延継続の行をまたぐ強調とリンク、見出し、段落の末尾の空白の combined のケースと、自由な中身の free のケースを足す
  - 各インライン構文を取り除いたときにその文字がテキストになり他が変わらないこと、置き換えた構文が使われること、2 つのスレッドで 1 つの構文セットを共有するパースを確かめる
  - 組み合わせと組み替えのテストが、すべての検査とともに通る
  - _Requirements: 1.1, 1.3, 1.7, 2.3, 7.2, 7.3, 7.7_

- [ ] 5.2 インラインの断片と msgstr の差し込みを確かめる
  - 引用の中のリストの段落を、別の文書の msgstr の断片で置き換え、中身が自由になり、インラインがトークンで覆われ、行の範囲と帯と style が残ることを確かめる
  - 挿入先の定義を使う指定の有無で、断片の参照のリンクが成り立つか成り立たないかが変わることを確かめる
  - fragment のテストが、置き換えた文書のロスレス性の検証とともに通る
  - _Requirements: 10.1, 10.2, 10.3, 10.4_

- [ ] 5.3 CommonMark spec 0.31.2 の準拠テストの構成を用意する
  - spec.txt と出典とライセンスの表示を置き、版と SHA-256 を 1 か所に定義し、構成で照合する（違えば構成を失敗させる）
  - ソースのアーカイブから除く指定、最上位のオプション `AMARK_REQUIRE_SPEC_TESTS`、CI の全ジョブでの必須の指定を足す
  - データがあれば例ごとのテストを生成して登録し、なければ必須の指定がないときはスキップとして報告し、あるときは構成を失敗させる
  - データのある構成で 652 のテストが登録され、データを除いた構成でスキップが報告され、必須の指定で構成が失敗することを確かめる
  - _Requirements: 12.3, 12.4, 12.5, 12.6_
