# Brief: markdown-renderer

## Problem
利用者は、Markdown をパースして木を編集し（例えば、翻訳のためにテキストを置換し）、Markdown に書き戻したい。そのとき、次の 3 つを満たす必要がある。
- 編集していない部分は、元の表記（マーカー、インデント、空白、改行コード、エスケープの書き方）のまま残る。
- 編集した部分だけが、正しい Markdown として作り直される。
- 無編集なら、元の入力とバイト単位で同じ出力になる。

ナイーブに作り直すと、次のような問題が起きる。
- テキストに `*` や `#` が入って構文が変わる。
- 複数行になったテキストで、引用の `> ` やリストのインデントが崩れる。
- 隣接するノードとの間で、区切り文字が予期せず結合する。

## Current State
まだ存在しない。`syntax-tree` の構文トークンと編集済みの追跡、そしてパーサ（`block-parser`、`inline-parser`）が記録する構文トークンの上に作る。

## Desired Outcome
- `amark_render_markdown(node, options, ...)` で木を Markdown に書き戻せる。
- **往復の保証**：無編集の木を書き戻すと、入力とバイト単位で同じ出力になる。任意の入力に対して成り立つことを、CommonMark spec の全例、コーパス、ファジングによるプロパティテストで確かめる。
- **差分的な作り直し**：
  - 編集したノードは、周りの元の表記（使われているマーカー文字、インデントの幅、改行コード）に合わせて作り直す。
  - 作り直すときは、文脈に応じた最小限のエスケープを行う。
  - コンテナの接頭辞を付け直す。
- **意味の保存**：編集後の木を書き戻して再パースすると、編集後の木と意味的に等しい木になる。これもプロパティテストで確かめる。
- 新しく作ったノード（構文トークンを持たないノード）は、オプションで設定できる正規化スタイルで出力する（強調のマーカー、リストのマーカー、見出しの形式、フェンスの文字など）。
- ノード型ごとの Markdown 出力のスロットを、構文拡張から登録できる。拡張ノード（表など）も、往復と差分的な作り直しに参加できる。

## Approach
- 書き戻しの手順：構文トークンを持ち、編集されていない部分木は、元のソース範囲をそのまま出力する。編集済みのノードとその祖先は、子ごとに「元のまま出す」か「作り直す」かを決めながら出力する。
- エスケープは、使われている構文セット（拡張を含む）を参照して、どの文字がその文脈で特別な意味を持つかを判断する。そのため、構文拡張の Markdown 出力のスロットには、エスケープが必要かどうかを問い合わせるフックを含める。
- 意味の保存の検証として、「出力を再パースして木を比較する」テスト用のユーティリティを用意する。

## Scope
- **In**：
  - Markdown レンダラの本体
  - 正規化スタイルのオプション
  - Markdown 出力のスロットのインタフェース
  - CommonMark の全ノードの Markdown 出力
  - 往復と意味の保存のプロパティテスト
  - テスト専用の検証用拡張（GFM 相当）の Markdown 出力に対応すること
- **Out**：
  - フォーマッタとしての整形機能（無編集の部分を書き換えること）。将来、オプションとして足す余地は残す。

## Boundary Candidates
- 元のまま出すか作り直すかの判定と、元の表記の出力
- 作り直しとエスケープ
- 正規化スタイル

## Out of Boundary
- パース
- HTML 出力
- 構文トークンのモデルの定義（`syntax-tree`）。ただし、不足が見つかったら `syntax-tree` とパーサの spec に戻って補う。

## Upstream / Downstream
- **Upstream**：`syntax-tree`、`block-parser`、`inline-parser`
- **Downstream**：利用者（翻訳などの編集ツール）

## Existing Spec Touchpoints
- **Extends**：`syntax-tree` の拡張記述子に、Markdown 出力のスロットを足す。テスト専用の検証用拡張（`inline-parser` が持つ）に、Markdown 出力を足す。
- **Adjacent**：`html-renderer`（レンダラのスロットの設計は揃える）

## Constraints
- 無編集の往復でバイト単位で同じ出力になることは必須である。次の入力でも成り立たなければならない。
  - タブ、CRLF、末尾の空白
  - 遅延継続行
  - NUL 文字や BOM を含む入力
- この spec の design で構文トークンに不足が見つかることを想定し、`syntax-tree`、`block-parser`、`inline-parser` に戻って直すことを許容する。
