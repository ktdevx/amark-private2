# Implementation Plan

> 前提：design.md の「Integration & Upstream Changes」の上流の変更（`foundation` のエラーコード、`block-parser` のバイト列の走査、`inline-parser` の flanking と照合と raw HTML の走査の公開・テキストの走査の規則・`gen_examples.cmake` の `CHECK=`・`gfm_inline_ext.h` の拡張オートリンクの役割の定数、`html-renderer` の `gen_html_cases.cmake` の `CHECK=` / `INCLUDE=`、`foundation` のテストの補助ライブラリとファジングの規則）は、それぞれの spec を更新して実装する。この spec が上流の所有するファイルに行う編集は、`tests/extensions/gfm_set.c` と `tests/extensions/CMakeLists.txt`（タスク 4.2）と、予定どおりの追記（`amark.h`、`extension.h`、`commonmark.c` の 1 行）だけである。タスク 1.1 はその有無を確かめるだけで、この spec の中で代わりを作らない。

- [ ] 1. 基盤：上流の前提、公開ヘッダ、ビルドとテストの補助
- [ ] 1.1 上流の前提が揃っていることを確かめる
  - 表現できないことを示すエラーコードとその文字列、HTML ブロックの開始と終わりの条件とタグのバイト列の走査、区切り文字の flanking と照合の純粋な関数、raw HTML のバイト列の走査、エスケープや文字参照を含むテキストの走査の一致を採らない規則、例の生成の検査の関数の指定、ケースの生成の検査の関数と include の指定、GFM 相当の検証用拡張の拡張オートリンクの役割の定数、spec.txt の版の定義、が上流にあることを確かめる小さなテストを作る
  - どれかが欠けていれば、この spec の作業を止めて、欠けている上流の変更を報告する（代わりの実装やラッパーを作らない）
  - 上流の関数を呼ぶ前提確認のテストがビルドされて成功する
  - _Requirements: 3.5, 4.1, 4.3, 10.4_

- [ ] 1.2 Markdown レンダラの公開ヘッダを宣言し、ソースをビルドに組み込む
  - オプション、報告、入口、2 種類のスロットの構造体、出力の文脈の API、区切り文字と行の表示の構造体、エスケープのユーティリティ、組み込みの出力の構文拡張の取得関数、CommonMark の補助関数、上限の定数を持つ公開ヘッダを、設計の依存の順で作る
  - 拡張のヘッダのスロットの種類の番号の節に、ノード型ごとの出力とフックの 2 つの番号と、この spec の範囲の注記を追記し、全体をまとめるヘッダに、foundation が定める正準の順に従って新しいヘッダを最後に加える
  - 設計の File Structure Plan のエンジンと組み込みの出力の各ソースと内部ヘッダをライセンスヘッダつきで作ってライブラリのソースに加え、公開の各関数に後のタスクで実装するまでの仮の定義（エラーコードを返す関数は不正な状態、ポインタは NULL、真偽は false、問い合わせは 0）を置く
  - 静的と動的の両方の構成で警告なしにビルドが成功し、公開ヘッダの単独コンパイルの検査（C と C++）が新しいヘッダについても成功する
  - _Requirements: 9.1, 13.1, 13.2_

- [ ] 1.3 テストの補助と生成テストの仕組みを作る
  - テストの補助を 2 つの INTERFACE ライブラリに分ける：Naos に依存しない検査の本体（判定を状態と失敗の説明で返す。ファジングのターゲットがリンクし、ファジングだけの構成でも定義される）と、Naos に依存する検査（構文セットと文書の用意、S 式から組み立てた木を出力して期待値と比べ、違えば両方を表示するマクロ、ケースの検査の関数）。どちらも公開 API だけで作り、Naos に依存しない方は Naos に依存しうる木の組み立ての補助にもリンクしない
  - 作り直しの表記のケースのデータ（html-renderer のケースの形式：名前とオプションの見出し、S 式、区切り、期待する Markdown、終わりの区切り）を、html-renderer のケースの生成のスクリプトに検査の関数と include を指定して生成テストにし、ブロックとインラインの 2 つの空のデータで登録する（生成のスクリプトを作らない）。検査の関数は未知のオプションを拒否する
  - 設計の手書きのテストのファイルを、空のテストのスイートとしてすべて作って登録する（後のタスクは自分のファイルだけを編集する）
  - ケースが 1 つもない状態で、構成とビルドとテストの実行が成功し、テストを作らずファジングだけを有効にした構成でも構成が成功する
  - _Requirements: 11.1, 11.5_

- [ ] 2. エンジン
- [ ] 2.1 (P) エスケープと文字参照のユーティリティを実装する
  - 指定した文字の集合のうち、ASCII の句読点はバックスラッシュで、それ以外は 10 進の数値文字参照で表すエスケープと、符号位置の数値文字参照の書き出しを、文書なしで使える関数として作る
  - ロケールに依存しない 10 進の変換を使い、失敗時に出力のバッファを元の長さに戻し、範囲外の符号位置と NULL の引数を規約どおり拒否する
  - テストで、0x00–0xFF の全バイトの結果、多バイトの UTF-8 の並びの保持、サロゲートと範囲外の拒否が確かめられる
  - _Boundary: MdEscape_
  - _Requirements: 3.3, 13.4_

- [ ] 2.2 (P) スロットの検査と、型ごとの連鎖の表とフックの一覧の構築を実装する
  - 構文セットのノード型ごとの出力のスロットを構文セットの順に集め、大きさ・必須の処理・ノード型の名前の解決を検査し、型の識別子で引く連鎖の表を作る
  - フックのスロットを構文セットの順に集め、大きさ・状態の大きさの上限・1 つの拡張に 1 つまでを検査し、照合の関数を持つ最初のフックを記録する
  - 確保は文書のアロケータで行い、失敗や検査の違反では作りかけの表を解放する
  - 内部用のテストで、不正なスロットのそれぞれが不正な引数になり、同じ型の複数のスロットが構文セットの順に並ぶことが確かめられる
  - _Boundary: MdDispatch_
  - _Requirements: 9.1, 9.3, 9.8_

- [ ] 2.3 (P) トークンの出力順の列挙と、元の行・タブの幅・改行コード・末尾の空行の判定を実装する
  - 部分木のすべてのトークンを、ソースと位置と部分的なタブの列の順に返すカーソルを、子孫と位置が重なるコンテナのトークンだけを深さで抑えた小さなヒープで合流させて作り、別のソースのトークンが混ざれば混在を返す
  - 位置からその元の行の先頭を求める関数、行の先頭から 4 列のタブストップで数えたタブの元の幅、文書の元の入力の最初の改行コード、部分木の末尾の空行（空白と改行だけの元の行の並び）を求める関数を作る
  - 内部用のテストで、手で組み立てたトークン（引用の接頭辞、遅延継続、部分的なタブ、CRLF、BOM、NUL）の木のカーソルの順がソースの順と一致し、タブの幅と末尾の空行が期待どおりになる
  - _Boundary: MdSource_
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.6, 8.4, 12.1_

- [ ] 2.4 出力先と行のため置き、元の表記の書き出しを実装する
  - バッファの出力先（開始時の長さを記録し、失敗で戻す）と、書き出しの関数の出力先（中継のバッファで 8 KiB ごとに渡し、終わりに残りを渡し、最初の失敗を保持する）を作る
  - 断片・アンカー・改行を持つ現在の行と、マークアップの書き出し、行の並びの書き出し、合成した改行、閉じていない行を新しい内容の前に合成した改行で閉じる規則、改行のない最後の行の保持を作る
  - 部分木の元の表記、自分のトークンの子の前と後ろ、トークン 1 つの書き出しを、カーソルを使って行に流す形で作り、改行コードのオプション（文書に合わせる、LF、CRLF）で合成した改行を書く
  - 内部用のテストで、無編集の文書の根の書き出しが入力とバイト単位で一致し（タブ、CRLF、行末の空白、NUL、BOM、改行のない最後の行）、書き出しの関数への出力の連結がバッファと同じで、失敗の保持と巻き戻しが確かめられる
  - _Depends: 2.3_
  - _Requirements: 1.2, 1.3, 1.4, 1.5, 2.1, 2.2, 2.4, 2.6, 6.4, 9.4_

- [ ] 2.5 接頭辞の積み重ね、元の接頭辞の選択、部分的なタブと列の規則を実装する
  - 接頭辞を持つコンテナに入ると積み、出ると降ろす積み重ねと、行を閉じるときに外側から最初の行・続く行・空行の種類で接頭辞の処理を呼ぶ仕組みを作る
  - 接頭辞の処理の中で、最初の行ではコンテナの最初の元の行の接頭辞のトークンを、それ以外ではアンカーの元の行の接頭辞のトークン（遅延継続を含み、最初の元の行のものを除く）を書く関数を作り、同じ元の行のアンカーを最初の 1 行だけに使う
  - 作り直す葉の改行の後の行で、葉がアンカーの元の行に持つ行頭の字下げを接頭辞の後に書く
  - 部分的なタブを、すべての部分を同じ行で元のまま出すときだけタブで、それ以外は列の数の空白で出し、合成した接頭辞や長さの違う断片の後ろの列に依存するタブを元の幅の空白にする
  - 内部用のテストで、移動したノードの接頭辞の合成と移動元の接頭辞が出ないこと、遅延継続の保持、引用の中のタブの分割の往復と空白への置き換え、合成した接頭辞の後ろのタブの幅、2 回目のアンカーの扱いが確かめられる
  - _Requirements: 2.2, 2.3, 8.1, 8.2, 8.3, 8.4, 9.5_

- [ ] 2.6 入口、オプション、たどり、ノードの扱いの判定、呼び出しの文脈、フックと報告を実装する
  - バッファと書き出しの関数の 2 つの入口で、引数とオプション（大きさ、未知のビット、選べない値、省略時の既定）を検査し、違反なら何も出力しない
  - 親と兄弟のリンクで反復して部分木をたどり、元の表記をそのまま出すノードはカーソルで出し、それ以外は連鎖の最後の処理を入るときと出るときに呼び、処理のない型は無編集なら元の表記を出し、そうでなければ表現できないとする
  - 呼び出しの文脈の保存と復元、前の処理の呼び出し、子の省略、現在の拡張と拡張の状態、状態の確保とフックの開始・終了・後始末の順、失敗時の後始末と巻き戻しを作る
  - 表現できないことの記録（最初の 1 つ）と、オプションの報告への理由・ノード・拡張の書き込み、文書の根の BOM の書き出し、インラインのノードを根にした出力を作る
  - テストで、根・途中・切り離したノードの出力、2 回の出力の一致、出力の前後で木のダンプ（トークンと編集の記録を含む）が同じこと、後の拡張の処理の優先と前の処理の呼び出し、処理のない型の無編集と編集、フックの順と状態、オプションの拒否と既定、報告の内容が確かめられる
  - _Depends: 2.2, 2.4, 2.5_
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 1.7, 4.1, 4.2, 4.4, 7.1, 7.2, 7.3, 7.5, 9.1, 9.2, 9.3, 9.9_

- [ ] 2.7 ノードの情報の表、状態の印、汚れの印、ブロックの区切りを実装する
  - 処理を呼ぶ部分の子の情報（状態の印、最初と最後の内容の元の位置と行、末尾の空行）を後順の 1 回のたどりで求め、ノードのポインタを鍵とする表に持ち、処理に状態の印を問い合わせる手段を作る
  - 汚れの印を付ける手段と、祖先への「汚れた子孫を持つ」の伝播（すでに持つ祖先で止める）を作り、汚れの印を持つノードを元の表記で出さないようにする
  - 元の隣接の判定、新しい隣接の印、親の空行のトークンの子の間への割り当て、空行の規則（元のまま、なし、空行が要る）、空行の合成、元の表記で出す子の末尾の空行の省略、新しい隣接で空行を置けないときの直後に置けるかの問い合わせと表現できないことの報告を作る
  - テストで、削除・移動・挿入による新しい隣接の判定、空行の規則の 3 つの振る舞い、直後に置けない組み合わせの報告、汚れの印による作り直しと局所性（無関係のブロックが元の表記のまま）が確かめられる
  - _Depends: 2.6_
  - _Requirements: 3.6, 5.1, 5.2, 9.4, 9.6, 12.1_

- [ ] 2.8 作り直す葉の断片、エスケープ、保護を実装する
  - 葉の中身の開始と終わりの間の書き出しを、テキスト・元のエスケープ・マークアップ・区切り文字の断片と中身の行としてため、改行を許さない葉での改行を表現できないとする
  - フックが足すエスケープの文字の集合と葉の追加の集合、符号化の手段の指定、テキストのノードの元のトークンの書き出し（元のエスケープと文字参照と置換を保つ）、値の書き出しを作る
  - 行の表示とバイトの分類を作って保護のフックを呼び、報告された範囲・エスケープの集合の文字・行頭と行末の空白・末尾の指定の文字・次の文字の要求を、素からバックスラッシュ、文字参照の方向にだけ強める符号化で解決し、保護できない範囲と符号化の手段がない場合を表現できないとする
  - 解決した行を、最初の元の位置の断片をアンカーとして行の書き出しに流す
  - 内部用のテストで、エスケープの集合の文字のエスケープと既存の表し方の保持、行頭と行末の空白の文字参照、末尾の `#` の保護、保護の範囲の符号化、次の文字の要求、符号化の手段のない構文セットの報告が確かめられる
  - _Depends: 2.5_
  - _Requirements: 3.3, 3.4, 3.8, 5.3, 9.4, 9.6, 9.7_

- [ ] 2.9 区切り文字の解決を実装する
  - 区切り文字の断片を開きと閉じの対にし、希望の文字を割り当て、同じ文字の隣り合う断片を並びにまとめて前後の出力の文字から開閉の可否を求め、照合の関数の結果を内側から断片に割り当てて意図した対と一致するかを検証する
  - 検証に失敗したら、隣と違う文字の選択、内側の空白と外側のテキストの文字の文字参照による単一の役割への調整、同じ文字の祖先の開きの確認による構成的な割り当てを行って再び検証し、満たせなければ区切りの問題として表現できないとする
  - 照合の関数を提供するフックがないときは構成的な割り当てだけを使う
  - 内部用のテストで、元の文字が成り立つ表記（3 の倍数の規則に頼るものを含む）が保たれること、内側の端の空白、単語の中の強調、直接入れ子の同じ種類、隣り合う強調、照合のない構成的な割り当て、満たせない組み合わせの報告が確かめられる
  - _Requirements: 3.5, 6.5, 9.7_

- [ ] 3. 組み込みの Markdown 出力
- [ ] 3.1 組み込みの出力の構文拡張の表とフックを作る
  - 19 のノード型のスロットとフックのスロットを持つ構文拡張を静的な記憶域で定義して取得関数で返し、各型の処理は後のタスクで実装するまで元の表記だけを出す仮の処理にする
  - フックの開始で、構文の拡張の有無、構文セットのインラインの文字の宣言の和のエスケープの集合への追加、バックスラッシュと文字参照の有無による符号化の手段、リンクの性質の型を求めて状態に持ち、行頭のブロックの構文の保護と、照合の関数（設計の対応の表どおりに並びと照合の結果を上流の形と写し合い、作業の配列を文書のアロケータで確保して使い回し、後始末で解放する）を作る
  - 項目の接頭辞の補助と CommonMark の flanking の補助の公開関数と、ブロックの「自分で閉じる」「段落の類」の共通の判定を作る
  - テストで、照合の関数の写し方（規則の値、上限から使える数への変換、長さの上限を超える並び、未知の規則の拒否、照合の数と添字の保持）が確かめられ、構文拡張の名前とスロットの数と型が設計どおりで、行頭の保護（`#`、`>`、`-`、`+`、`=`、`~`、数字と区切り、段落を中断する HTML の開始のマークアップ）、構文を取り除いた構文セットでの符号化の手段とエスケープの集合が期待どおりになる
  - _Depends: 2.6, 2.8, 2.9_
  - _Requirements: 3.3, 3.8, 9.2_

- [ ] 3.2 (P) コンテナのブロック（文書、引用、リスト、項目）の出力を実装する
  - 引用と項目の接頭辞（元の接頭辞の再利用、合成、空行での表し方）、リストと項目の空行の規則（tight、編集した loose、元のまま）、リストのマーカーの選択（最初の項目のトークン、オプション、前の兄弟の同じ種類のリストとの違い）、項目の番号（最初は開始番号、新しい項目は前の番号 ＋ 1）、マーカーの幅の変化での続く行の合成、直後に置けるかの判定を、設計の表どおりに作る
  - ブロックのケースのデータに、新しいリストと項目の表記、入れ子のコンテナ、マーカーの切り替え、開始番号の変更を書く
  - ブロックの生成テストの該当するケースと、項目の移動・挿入・削除、tight と loose の切り替え、隣り合う同じ種類のリストの手書きのテストが成功する
  - _Boundary: CoreMarkdown（コンテナ）_
  - _Depends: 3.1_
  - _Requirements: 3.6, 5.4, 6.2, 6.3, 8.1, 8.5, 8.6_

- [ ] 3.3 (P) テキスト、改行、コード、HTML のインラインの出力を実装する
  - テキストの編集と無編集の書き出し、ソフトブレークの改行のトークンだけの再利用と合成、ハードブレークの表記と葉の末尾での報告、コードスパンのフェンスの長さと詰め物と隣り合うコードスパンの報告、インラインの HTML のリテラルの検査（上流の走査）と複数行の書き出しを、設計の表どおりに作る
  - インラインのケースのデータに、特別な文字を含むテキスト、行頭と行末の空白、改行の前の空白、バッククォートを含むコード、空白だけのコード、複数行の HTML を書く
  - インラインの生成テストの該当するケースと、隣り合うコードスパン・段落の末尾のハードブレーク・成立しない HTML の報告のテストが成功する
  - _Boundary: CoreMarkdown（インラインの葉）_
  - _Depends: 3.1_
  - _Requirements: 3.3, 3.4, 4.3, 5.3, 6.1_

- [ ] 5.1 往復と作り直しのプロパティの検査と、コーパスと spec.txt の生成テストを作る
  - 往復（根とトップレベルのブロックの部分木）、トークンを取り除いた木の作り直し、全ノードを編集済みにした木の出力のそれぞれで、再パースして意味的に等しいことを確かめ、表現できないと報告されたら失敗にする検査と、それらをまとめた例の検査の関数を作る
