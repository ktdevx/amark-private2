# Implementation Plan

> この計画は、2026-11-27 の design（`syntax-tree` の「行 × 帯」と「中身の上の CST」のモデルに合わせた版）だけに基づく。前の版の tasks は引き継がない。
> 公開ヘッダは、宣言した関数をすべて実装していないとエクスポートの検査に通らない。各タスクは、自分が実装した関数だけを `html.h` に宣言して足す。`html.h` に宣言を足すタスクは並列にしない。
> 値、タイト、位置は `syntax-tree` の公開の問い合わせだけから取る。綴りを読む処理、定義の表、タイトの判定、位置の計算を作らない。

- [ ] 1. 基盤：公開ヘッダとビルドの骨組み
- [ ] 1.1 HTML の公開ヘッダとビルドとテストの登録の骨組みを作る
  - 出力先の書き出しの関数の型だけを持つレンダラの共通ヘッダと、オプション、ソフトブレークの列挙、書き出しの分類の列挙、不透明な出力の文脈の型、2 つのスロットの構造体、フラグと上限のマクロだけを持つ HTML のヘッダを作る（関数の宣言はまだ持たない）。スロットの種類の番号は既存の拡張のヘッダのものを使い、定義し直さない。
  - まとめのヘッダの 3 番目の組の位置に、2 つのヘッダをこの順で含める。
  - レンダラの層と組み込みの構文の層のソースを、design の File Structure Plan のファイル名で最小の内容で作り、ライブラリのソースの一覧に加える。HTML のテストのディレクトリを、Naos を使うターゲットと使わないターゲットを分けた形でテストの登録に加える。
  - 全構成（静的と動的、サニタイザ）でビルドが警告なしに通り、公開ヘッダの名前と順の検査、エクスポートの検査、ライセンスヘッダの検査を含む既存のテストがすべて通る。
  - _Requirements: 12.1_

- [ ] 2. エンジン：エスケープ、書き出し、スロットの解決、たどり、文脈、フック
- [ ] 2.1 エスケープと URL のユーティリティを実装する
  - HTML のエスケープ、href のエスケープ、危険な URL の判定を、文書と文脈なしに使える関数として公開する。失敗したら出力のバッファを呼び出し前の長さに戻す。
  - 出力の書き出しが中間のバッファなしにエスケープできるよう、1 バイトの置き換えと href の安全なバイトの判定を内部に提供する。
  - 0x00–0xFF の全バイトの HTML と href のエスケープの結果が表と一致し、`data:image/pn`、`javascript`、大文字の `JAVASCRIPT:`、空の判定と、多バイトの UTF-8 が HTML のエスケープで変わらないことが、エスケープのテストで確かめられる。
  - _Requirements: 4.2, 4.4, 6.1, 6.2, 6.3, 6.4, 12.7_

- [ ] 2.2 出力先と分類つきの書き出しを実装する
  - バッファの出力先（開始時の長さを覚えて直接追加し、失敗で戻す）と、書き出しの関数の出力先（8 KiB の中継のバッファ）を作る。
  - マークアップ、エスケープしたテキスト、URL（安全判定つき）、生の HTML（安全モードではコメントに置き換え）の書き出しと、`cr` の判定（フィルタの前の最後のバイト）を実装する。長さ 0 の書き出しは何も渡さない。
  - 最初の失敗を保持し、以後の書き出しが何もせずにその失敗を返すようにする。フィルタの連鎖への中継と、フィルタの外での中継の拒否を実装する。
  - INTERNAL の出力のテストで、文脈を直接組み立てて、各書き出しの分類と内容、`cr`、書き出しの関数の失敗の即時の返却、連結がバッファの出力と一致すること、フィルタの順と省略が確かめられる。
  - _Requirements: 1.2, 1.3, 1.4, 4.5, 4.6, 8.1, 9.6, 9.7, 12.2_

- [ ] 2.3 ソース位置の属性の書き出しを実装する
  - ソース位置のフラグがあるときだけ、ノードについて構文木のソース上の範囲を 1 回問い合わせ、位置があれば cmark の書式で始まりの行と列、終わりの行と列を書く。位置がなければ何も書かない。問い合わせの失敗は最初の失敗として返す。数はロケールに依存しない変換で書く。
  - 出力のテストで、ソースを登録して組み立てた木の引用、引用の中の段落、2 つ目のソースのブロック、行の範囲のない新しいブロック、空の範囲の属性が、構文木の範囲の値と一致することが確かめられる。
  - _Requirements: 5.1, 5.2, 5.3, 8.2, 12.5_

- [ ] 2.4 スロットの検査と連鎖の表を実装する
  - 文書の構文セットから、ノード型ごとの出力のスロットを構文セットの順に列挙して検査し（大きさ、必須の処理、型の名前の検索）、型の識別子で引く通常の処理とテキストだけのモードの処理の連鎖の表を作る。
  - 出力の前後のフックのスロットを列挙して検査し（大きさ、状態の大きさの上限、1 つの拡張に 1 つ）、フックの一覧とフィルタの一覧を作る。
  - INTERNAL のスロットの解決のテストで、連鎖の順、テキストだけのモードの連鎖、構文セットにない型の名前・処理のないスロット・小さいスロット・2 つ目のフックのスロットの拒否、HTML のスロットだけの拡張と別の種類のスロットを持つ拡張が確かめられる。
  - _Requirements: 7.1, 7.2, 7.6, 7.8, 9.1, 10.4, 12.4_

- [ ] 2.5 出力の入口と部分木のたどりを実装する
  - バッファと書き出しの関数の 2 つの入口と、オプションの初期化を公開する。オプションの大きさ、未知のフラグ、範囲外のソフトブレークを出力の前に拒否し、省略時は既定を使う。
  - ノードの関係の関数で、再帰なしに部分木を入る・出るの順にたどり、各ノードの連鎖の最後の処理を呼ぶ。処理のない型は子だけを出し、子の省略の求めに従う。前の処理の呼び出しは、現在のノードとイベントのときだけ 1 つ前を呼び、なければ処理のない場合の振る舞いをする。
  - 失敗したらたどりを止め、バッファを戻し、確保したものを解放して最初の失敗を返す。
  - 入口のテストとスロットのテストで、文書の根・木の途中・切り離したノードの出力、バッファの既存の内容への追加、処理の失敗でバッファが戻ること、出力の前後でダンプが同じこと、2 回の出力が同じこと、後の拡張の優先と包み込み、子の省略、オプションの拒否と既定が、テスト用の拡張で確かめられる。
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 1.7, 5.6, 5.7, 5.8, 7.2, 7.3, 7.4, 7.5, 7.7, 12.3_

- [ ] 2.6 出力の文脈を実装する
  - オプションの問い合わせ、部分木の根、深さごとの子のタイトさの設定と問い合わせ（部分木の根では偽）を実装する。
  - テキストだけのモードの開始と問い合わせと、テキストだけのモードの前の処理の呼び出しを実装する。開始したノードの子孫にだけ適用し、そのノードの出るときの処理は通常のモードで呼ぶ。
  - 同じ文書の任意のノードの入れ子の出力を、同じ出力先・オプション・フィルタ・状態と新しい深さの文脈で行い、上限を超えたら上限の超過を返す。処理の外の操作、現在でないノードの前の処理、別の文書のノードを拒否する。
  - 文脈のテストで、独自のコンテナが設定したタイトさを子が使い孫が使わないこと、テキストだけのモードの処理と処理を持たない型の振る舞い、切り離したノードの入れ子の出力、33 段の入れ子での上限の超過、誤用の拒否が確かめられる。
  - _Requirements: 8.2, 8.3, 8.4, 8.5, 8.7, 8.8, 8.9_

- [ ] 2.7 出力の前後のフックと拡張ごとの状態を実装する
  - 出力ごとに状態を 0 で確保し、開始の前の処理を構文セットの順に、終了の後の処理と後始末を逆の順に呼ぶ。失敗したら終了の後の処理を飛ばし、後始末と解放は必ず行う。
  - 現在の処理の拡張と、拡張の状態の問い合わせを公開する。フックとフィルタを、利用者が求めたすべての部分木の出力で使う。
  - フックとフィルタのテストで、開始の前の出力が先頭に、終了の後の出力が末尾に来ること、3 つの拡張での順、状態が 0 で始まり失敗でも後始末が呼ばれること、ノードの処理から状態を引けること、分類つきのフィルタが変えて渡す・省くこと、部分木の出力でも動くこと、フィルタの中の通常の書き出しの拒否が確かめられる。
  - _Requirements: 9.1, 9.2, 9.3, 9.4, 9.5, 9.6, 9.7, 9.8_

- [ ] 3. 組み込みの HTML 出力とテストの基盤
- [ ] 3.1 組み込みの拡張の骨組みと、テストの補助と共有のケースの生成スクリプトを作る（統合のタスク）
  - 組み込みの HTML 出力の構文拡張を、名前とスロットの表（この時点では空）だけを持つ静的な拡張として作り、取得の関数を公開する。値を読む補助（構文木の値の問い合わせを呼んで失敗をそのまま返す）も作る。3.2 と 3.3 が表にスロットを足す。
  - テストの補助を作る：構文セットの用意（組み込みの拡張、与えた拡張の順に足して凍結する）、ソースの登録と S 式からの組み立てと出力、出力の照合のマクロ、生成テストの検査関数（オプションの語 `unsafe` と `softbreak=` の解釈、未知の語の拒否）。
  - design の契約どおりに、ケースのデータから Naos のテストを生成する汎用のスクリプトを作り、名前の重複と形の崩れを生成の失敗にする。
  - テスト用の拡張だけを使う小さなケースのファイルで、生成テストが登録され期待どおりに通ることと、壊れたファイルで生成が失敗することが確かめられる。組み込みの拡張を加えた構文セットが凍結できる。
  - _Boundary: CoreHtml, HtmlTestSupport, HtmlTests_
  - _Requirements: 10.1, 10.2, 11.6_

- [ ] 3.2 ブロックの 10 型の出力を実装する
  - document、block_quote、list、item、code_block、html_block、paragraph、heading、thematic_break、link_definition の出力を design の表のとおりに実装し、組み込みの拡張の表に加える。リストの種類と開始番号、見出しのレベル、情報文字列、コードと HTML の内容は構文木の値で読み、項目は親のリストのタイトの値で子のタイトさを設定する。
  - ブロックのケースのデータで、design の表の各分岐（ul/ol と開始番号、情報文字列の 4 つの形、記録したタイトの真偽、項目と引用の中の段落、入れ子のリスト、リンク参照定義、文書の子だけ）が cmark と同じ期待値で通る。
  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.7, 2.8, 3.1, 3.6, 4.1, 5.1, 10.1, 10.2_

- [ ] 3.3 インラインの 9 型の出力を実装する
  - text、softbreak、linebreak、code、html_inline、emph、strong、link、image の出力とテキストだけのモードの出力を、design の表のとおりに実装し、組み込みの拡張の表に加える。
  - リンクと画像の宛先とタイトルは構文木の値で読み、解決できない参照は宛先を空、タイトルをなしとして扱う。画像は代替テキストをテキストだけのモードで出す。ソフトブレークはオプションに従う。
  - インラインのケースのデータで、タイトルの有無、画像の代替テキストの中の強調・コード・リンク・改行・生の HTML、3 つのソフトブレークの出し方が cmark と同じ期待値で通る。
  - _Requirements: 2.1, 2.5, 2.6, 2.9, 3.1, 3.3, 3.5, 4.1, 4.3, 5.4, 5.5, 8.6_

- [ ] 3.4 構文木の値に従う出力を確かめる
  - 値のテストで、値の設定の後の出力、綴りを捨てる前後で同じ出力、full と shortcut のリンクと画像の定義の値、定義の変更と切り離しの反映、定義のない参照の出力、切り離した部分木の中のリンクが文書の定義で解決されること、空行から導くタイトと上書きと上書きの取り消し、`&#10;` から導いた改行を含むテキストと空のコードの出力を確かめる。
  - 値のテストがすべて通り、出力が綴りの状態によらないことが確かめられる。
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 3.7_

- [ ] 3.5 安全モードとオプションを組み込みの出力で確かめる
  - 安全モードのテストで、既定での生の HTML の省略、危険なスキーム（大文字を含む）の宛先が空になることと画像の種類の `data:` が残ること、生の HTML の許可での出力とエスケープ、拡張の生の HTML の書き出しが同じ規則に従うこと、テキスト・タイトル・情報文字列・代替テキストのエスケープを確かめる。
  - オプションのテストで、ソースを登録した木のすべてのブロックの要素のソース位置の属性と、新しいブロックに属性がないことを確かめる。
  - 安全モードとオプションのテストがすべて通る。
  - _Requirements: 4.1, 4.2, 4.3, 4.4, 4.5, 4.6, 5.1, 5.2, 5.3, 10.3_

- [ ] 4. GFM 相当の検証用拡張
- [ ] 4.1 検証用のノード型と、表と取り消し線の出力を作る
  - Naos に依存しない INTERFACE のライブラリとして、design の表の 7 つの検証用のノード型の記述子（値と style の項目、印、包含）を作る。表の列の揃えの文字列を検査する。
  - 表（見出しの行、本体の行、列の揃え、列の番号を状態に置く）と取り消し線の HTML のスロットと拡張の記述子を、公開 API だけで作る。
  - 検証用のテストで、揃えのある表、本体のない表、取り消し線（テキストだけのモードを含む）が cmark-gfm と同じ形の期待値で通る。
  - ファジングだけの構成（Naos なし）でも検証用のライブラリが定義されてビルドでき、そのソースが公開ヘッダだけを含めることが確かめられる。
  - _Requirements: 11.1, 11.2, 11.6, 12.1_

- [ ] 4.2 タスクリストとタグフィルタの出力を作る
  - タスクリストの項目の出力を、リストのタイトの値で子のタイトさを設定する形で作る。
  - タグフィルタを、html_block と html_inline の処理の差し替えと、生の HTML の分類のフィルタの 2 つの方式で作る。
  - 検証用のテストで、タイトとルーズのタスクリスト、2 つの方式のタグフィルタ（`<script>`、`</style>`、`<SCRIPT >`、対象外の `<scripts>`、テキストの `&lt;script&gt;`）が期待値で通る。
  - _Requirements: 11.3, 11.5, 11.6_

- [ ] 4.3 脚注の出力を作る
  - 参照の番号付け（正規化したラベルの出現順、2 回目以降の id）、定義の記録と子の省略、終了の後のフックでの末尾の出力（入れ子の出力と戻りのリンク）、後始末を、公開のスロットとフックと構文木のラベルの正規化だけで作る。木を変えない。
  - 検証用のテストで、同じ参照の 2 回目、参照されない定義、定義の中の複数の段落、最後の子が段落でない定義、定義のない参照、大文字小文字の違うラベルが期待値で通り、出力の前後で木のダンプが同じことが確かめられる。
  - _Requirements: 11.4, 11.6_

- [ ] 5. 統合と検証
- [ ] 5.1 公開 API の検査に HTML の関数を加える
  - C++ からの include のテストで、HTML のヘッダの関数（オプションの初期化、エスケープ、組み込みの拡張の取得、出力の入口）を呼ぶ。
  - C++ のテスト、公開ヘッダの名前と順の検査、エクスポートの検査が、静的と動的の両方の構成で通る。
  - _Requirements: 12.1_

- [ ] 5.2 (P) HTML の出力のファジングのターゲットを作る
  - 入力をオプションと木の組み立ての操作列（組み込みの型の生成と挿入、値の設定と記録、リンク参照定義とラベル、切り離し）として公開 API で解釈し、確保の失敗を注入しながらバッファと書き出しの関数へ出力するターゲットと種のコーパスを作る。
  - コーパスの再生で異常終了とリークがなく、成功した出力が正しい UTF-8 で、安全モードでは生の HTML と危険な URL が出力に現れないことが確かめられる。
  - _Boundary: HtmlFuzz_
  - _Requirements: 4.1, 4.2, 12.7_

- [ ] 5.3 (P) 確保の失敗の総当たりを行う
  - 組み込みの全型を含む木（ソース位置の属性あり、参照の形のリンクを含む）のバッファと書き出しの関数への出力、状態を持つフックの拡張、入れ子の出力を、確保の失敗の総当たりで実行する。
  - どの失敗の位置でもメモリ不足が返り、リークがなく、バッファが呼び出し前の長さで、すべての確保がテスト用のアロケータを通ることが確かめられる。
  - _Boundary: HtmlTests_
  - _Requirements: 1.5, 12.2_

- [ ] 5.4 深い木と計算量を確かめる
  - ソース位置の属性なしで深さ 10 万の引用の鎖と強調の鎖を出力し、期待する長さとタグの数を確かめる。ノードの数を 10 倍にしたときの時間と、HTML のスロットを 1000 持つ構文セットでの出力を確かめる。
  - ソース位置の属性ありで、深さ 1000 の引用の鎖と、10 万の段落を持つ平らな文書を出力し、平らな文書の時間がノードの数に線形であることを確かめる。
  - 規模のテストがスタックあふれなしに通る。
  - 5.3 と同じテストの登録のファイルを編集するので、並列にしない。
  - _Requirements: 12.3, 12.4, 12.5_

- [ ] 5.5 全構成で全体のテストを通す
  - 静的、動的、サニタイザ、ファジングだけの各構成で、ビルドとすべてのテストを実行する。静的なデータがすべて `const` で、アロケータの設定のほかにグローバルな可変状態がないことをレビューで確かめる。
  - すべての構成でビルドが警告なしに通り、すべてのテストが通る。
  - _Requirements: 12.1, 12.6_
