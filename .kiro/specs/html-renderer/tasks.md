# Implementation Plan

- [ ] 1. 基盤：公開ヘッダ、ビルドへの組み込み、テストの補助
- [ ] 1.1 HTML レンダラの公開ヘッダを宣言し、ソースとテストをビルドに組み込む
  - レンダラが共有する出力先の書き出しの関数の型を持つヘッダと、HTML のオプション・入口・2 種類のスロットの構造体・出力の文脈の API・出力の分類・エスケープと URL のユーティリティ・組み込みの HTML 出力の構文拡張の取得関数・上限の定数を持つヘッダを、設計の依存の順で作る
  - 拡張のヘッダのスロットの種類の番号の節に、ノード型ごとの出力とフックの 2 つの番号と、この spec の番号の範囲の注記を追記する
  - 全体をまとめるヘッダの、foundation の design が定める正規の include の順の「`render.h`、`html.h`」の位置に、2 つのヘッダを設計の順で追加する
  - 設計の File Structure Plan の `src/render/` と `src/syntax/` の HTML の各ソースと内部ヘッダをライセンスヘッダつきで作ってライブラリのソースに加え、テストのディレクトリとファジングのターゲットの登録先を構成に加える
  - 公開の各関数に、後のタスクで実装するまでの仮の定義（エラーコードを返す関数は不正な状態、ポインタを返す関数は NULL、真偽を返す関数は false）を置き、ライブラリとテストのリンクが成功するようにする
  - 静的と動的の両方の構成で警告なしにビルドが成功し、foundation の公開ヘッダの単独コンパイルの検査（C と C++）が新しい 2 つのヘッダについても成功する
  - _Requirements: 11.1_

- [ ] 1.2 テストの補助（構文セットと木の用意、出力の照合）と生成テストの仕組みを作る
  - 組み込みの HTML 出力の構文拡張と追加の拡張から凍結した構文セットを作る補助、S 式から木を組み立ててバッファに出力する補助、出力と期待値を比べて違えば両方を表示するマクロを、公開 API だけで作る
  - ケースのデータ（名前とオプションの見出し、S 式、区切り、期待する出力、終わりの区切り）からテストを生成するスクリプトを、foundation のテスト生成の補助を使い、設計の「共有のケースの生成スクリプト（契約）」のとおり HTML に固有の知識を持たない形（オプションの語をそのまま渡す、検査関数とヘッダを引数で選べる）で作り、HTML の検査関数を補助に置いて、ブロックとインラインの 2 つの空のデータのファイルで生成テストを登録する
  - 生成スクリプトが、検査関数とヘッダを引数で差し替えた別の登録でも使えること、形の崩れたケースと名前の重複で生成が失敗することを確かめられる
  - 設計の File Structure Plan の手書きのテストのファイルを、空のテストのスイートとしてすべて作って登録する（後のタスクは自分のファイルだけを編集する）
  - 生成テストと手書きのテストの登録が構成に入り、ケースが 1 つもない状態でも構成とビルドとテストの実行が成功する
  - _Requirements: 10.6_

- [ ] 2. エンジン
- [ ] 2.1 (P) エスケープと URL の判定のユーティリティを実装する
  - HTML のエスケープ（4 文字）、href のエスケープ（安全な文字の集合、`&` と `'` の文字参照、それ以外の大文字の百分率符号化、`%` はそのまま）、大文字と小文字を区別しない危険なスキームの判定（画像の 4 種類の `data:` は安全）を、文書なしで使える公開の関数として作る
  - 出力の処理が直接エスケープしながら書けるよう、1 バイトの置き換えと href の安全な文字の判定を内部の関数として提供する
  - 失敗時に出力のバッファを元の長さに戻し、NULL の引数を規約どおり拒否する
  - テストで、0x00–0xFF の全バイトのエスケープの結果が設計の表と一致し、危険な URL の判定の境界と多バイトの UTF-8 の並びの保持が確かめられる
  - _Boundary: HtmlEscape_
  - _Requirements: 3.2, 3.4, 5.1, 5.2, 5.3, 5.4, 11.6_

- [ ] 2.2 (P) スロットの検査と、型ごとの連鎖の表とフックの一覧の構築を実装する
  - 文書の構文セットからノード型ごとの出力のスロットを構文セットの順に集め、大きさ・必須の処理・ノード型の名前の解決を検査し、型の識別子で引く通常の連鎖とテキストだけのモードの連鎖を作る
  - フックのスロットを構文セットの順に集め、大きさ・状態の大きさの上限・1 つの拡張に 1 つまでを検査し、フィルタを持つものの順の一覧を作る
  - 確保は文書のアロケータで行い、失敗や検査の違反のときは作りかけの表を解放する
  - 内部用のテストで、不正なスロットのそれぞれが不正な引数になり、同じ型の複数のスロットが構文セットの順に並び、HTML のスロットだけを持つ拡張と他の種類のスロットを持つ拡張が同じ規則で扱われることが確かめられる
  - _Boundary: HtmlDispatch_
  - _Requirements: 6.1, 6.2, 6.6, 6.7, 6.8, 8.1, 9.4, 11.4_

- [ ] 2.3 出力先と分類つきの書き出しを実装する
  - バッファの出力先（開始時の長さを記録し、失敗で戻す）と、書き出しの関数の出力先（中継のバッファで 8 KiB ごとに渡し、終わりに残りを渡す）を作る
  - マークアップ、エスケープしたテキスト、安全判定つきの URL、安全モードに従う生の HTML の書き出し、直前の出力に基づく改行、ソース位置の属性（終わりの改行を除き、最後のバイトを含む列）の書き出しを、設計の分類の表どおりに作る
  - フィルタの連鎖（構文セットの順、次への受け渡し、フィルタの中の通常の書き出しの拒否）と、最初の失敗の保持を作る
  - 内部用のテストで、各書き出しの分類と内容、改行の判定がフィルタの前の出力に基づくこと、書き出しの関数の失敗が保持されて以後何も渡らないこと、トークンを付けたノードのソース位置の値が確かめられる
  - _Depends: 2.1_
  - _Requirements: 1.2, 1.3, 1.4, 3.5, 3.6, 4.1, 4.2, 7.1, 7.2, 8.6, 8.7, 11.2_

- [ ] 2.4 入口、オプションの検査、部分木のたどり、前の処理の呼び出しを実装する
  - バッファと書き出しの関数の 2 つの入口で、引数とオプション（大きさ、未知のビット、省略時の既定）を検査し、違反なら何も出力しない
  - 親と兄弟のリンクで反復して部分木をたどり、各ノードに入るときと出るときに連鎖の最後の処理を呼び、処理のない型は子だけを出し、子の省略を求められたら出るときへ進む
  - 呼び出しの文脈を保存・設定・復元し、現在のノードに対してだけ 1 つ前の処理を呼べるようにし、処理の外や現在でないノードでの誤用を設計どおりに拒否する
  - 深さごとの文脈の動的な配列で、親が直接の子に設定するタイトさを管理する
  - 失敗の時点で出力を止め、表を解放し、バッファを元の長さに戻す
  - テストで、木の途中と切り離したノードの出力、バッファの既存の内容の後ろへの追加、書き出しの関数の連結の一致、処理の失敗での復元、木が変わらないこと、2 回の出力の一致、後の拡張の処理の優先と前の処理による包み込み、子の省略、タイトさが直接の子だけに伝わること、オプションの拒否と既定が確かめられる
  - _Depends: 2.2, 2.3_
  - _Requirements: 1.1, 1.4, 1.5, 1.6, 1.7, 4.6, 4.7, 6.2, 6.3, 6.4, 6.5, 7.3, 7.9, 11.3_

- [ ] 2.5 テキストだけのモードと入れ子の出力を実装する
  - 入るときの処理がテキストだけのモードを求めたら、そのノードの子孫をテキストだけのモードの連鎖で出力し（処理のない型は子だけ）、そのノードの出るときの処理を通常のモードで呼ぶ
  - 同じ文書の任意のノードの部分木を、同じ出力先・オプション・フィルタ・状態で、通常のモードと新しい深さの文脈から出力する手段を作り、入れ子の上限を超えたら上限の超過を返し、別の文書のノードを拒否する
  - テストで、独自の型が開始したテキストだけのモード、独自の型のテキストだけのモードの処理、切り離したノードの入れ子の出力、33 段の入れ子での上限の超過、別の文書のノードの拒否が確かめられる
  - _Requirements: 7.4, 7.5, 7.7, 7.8, 7.9_

- [ ] 2.6 出力の前後のフックと拡張ごとの状態を実装する
  - 状態を 0 で埋めて確保し、開始の前の処理を構文セットの順に、終了の後の処理を逆の順に呼び、成否にかかわらず後始末を逆の順に呼んでから解放する
  - 現在の処理を持つ拡張と、拡張の状態を引く手段を作り、フックの中ではそのフックの拡張を現在の拡張とする
  - 文書の根でない部分木の出力でもフックとフィルタを使い、入れ子の出力ではフックを呼ばない
  - テストで、開始の前の出力が先頭に、終了の後の出力が末尾に来ること、3 つの拡張での呼び出しの順、失敗した出力でも後始末が呼ばれること、ノードの処理から状態を引けること、2 つのフィルタの順と分類による選択・変更・省略、部分木の出力でのフックが確かめられる
  - _Requirements: 8.1, 8.2, 8.3, 8.4, 8.5, 8.6, 8.7, 8.8_

- [ ] 3. 組み込みのノード型の HTML 出力
- [ ] 3.1 組み込みの HTML 出力の構文拡張の表と取得関数を作る
  - 19 のノード型のスロットを識別子の順に持ち、ノード型とパースのスロットを持たない構文拡張を静的な記憶域で定義し、取得関数で返す
  - ブロックとインラインの実装のファイルに 19 のスロットの定義を置き、それぞれの処理は 3.2 と 3.3 で実装するまで、何も出力しない仮の処理にする
  - テストで、構文拡張の名前とスロットの数と型の名前が設計どおりで、それを加えた構文セットが凍結でき、含めない構文セットでは組み込みの型が子だけを出すことが確かめられる
  - _Requirements: 9.1, 9.2, 9.4_

- [ ] 3.2 (P) ブロックの組み込みの型の出力を実装する
  - document、block_quote、list、item、code_block、html_block、paragraph、heading、thematic_break、link_definition の処理を、設計の出力の表どおりに公開 API だけで作る（情報文字列の最初の語と `language-` の重複の回避、開始番号の属性、項目による子のタイトさの設定、段落のタイトさの判定、リンク参照定義は何も出さない）

  - ブロックの生成テストがすべて成功する
  - _Boundary: CoreHtml（ブロック）_

  - _Requirements: 2.1, 2.2, 2.3, 2.4, 2.7, 2.8, 3.1, 4.1_

- [ ] 3.3 (P) インラインの組み込みの型の出力を実装する
  - text、softbreak、linebreak、code、html_inline、emph、strong、link、image の通常の処理とテキストだけのモードの処理を、設計の出力の表どおりに公開 API だけで作る（ソフトブレークのオプション、URL の安全判定、タイトルの有無、画像の代替テキストのテキストだけのモード）
  - インラインのケースのデータに、表の各分岐（タイトルの有無、画像の代替テキストの中の強調・コード・リンク・改行・生の HTML、ソフトブレークの 3 つのオプション）を cmark と同じ期待値で書く
  - インラインの生成テストがすべて成功する
  - _Boundary: CoreHtml（インライン）_
  - _Depends: 3.1_
  - _Requirements: 2.1, 2.5, 2.6, 2.9, 3.1, 3.2, 4.3, 4.4, 4.5, 7.6_

- [ ] 3.4 安全モード、オプション、上書きの規則を組み込みの出力で検証する
  - 既定で生の HTML がコメントになること、危険なスキーム（大文字を含む）の宛先が空になり画像の `data:` が残ること、生の HTML を許可したときの出力、拡張の生の HTML の書き出しが同じ規則に従うこと、テキスト・タイトル・情報文字列・代替テキストの特殊文字がすべてエスケープされることのテストを作る
  - トークンを付けた木で、ブロックの要素のソース位置の属性と、トークンのないノードに属性が出ないことのテストを作る
  - 組み込みの構文拡張の後に置いた拡張の処理が使われ、そこから組み込みの処理を呼べることのテストを作る
  - 安全モード、オプション、上書きのテストがすべて成功する
  - _Requirements: 3.1, 3.2, 3.3, 3.4, 3.5, 3.6, 4.1, 4.2, 9.3_

- [ ] 4. GFM 相当の HTML の検証用拡張
- [ ] 4.1 表、取り消し線、タスクリストの検証用の部品を作る
  - テストにだけ置くライブラリに、表・行・セル、取り消し線、タスク項目のノード型と型のデータ、HTML のスロット、拡張の記述子を、公開 API だけで部品ごとに公開する
  - このライブラリは Naos に依存させず（Naos の照合の補助は含めない）、foundation の規則に従ってファジングだけを有効にした構成でも定義されるようにし、テストを無効にしてファジングを有効にした構成で構成が成功することを確かめられる
  - 表は見出しの行と最初の本体の行の前の区切り、列の揃え、本体のない表を cmark-gfm と同じ形で出し、タスク項目はチェックボックスを出して子のタイトさを設定する
  - テストで、揃えと本体なしの表、取り消し線（代替テキストの中を含む）、タイトとルーズのタスクリストの出力が cmark-gfm と同じ形の期待値と一致する
  - _Requirements: 10.1, 10.2, 10.3, 10.6_

- [ ] 4.2 脚注の検証用の部品を作る
  - 参照と定義のノード型、参照の出現順の番号と定義の記録を持つ拡張の状態、定義をその場で出さない処理、終了の後のフックで参照された定義を番号の順に入れ子の出力で末尾にまとめる処理、最後の段落の終わりの前に戻りのリンクを差し込む段落の処理の包み込み、状態を解放する後始末を作る
  - テストで、同じラベルの 2 回目の参照、参照されない定義、複数の段落を持つ定義、脚注のない文書の出力が cmark-gfm と同じ形の期待値と一致し、テスト用アロケータでリークがない
  - _Requirements: 10.4, 10.6_

- [ ] 4.3 タグフィルタの 2 つの方式の検証用の部品を作る
  - 生の HTML のノード型の処理の差し替え（生の HTML を許可したときだけ対象のタグ名の `<` を置き換え、安全モードでは前の処理に委ねる）と、生の HTML の分類の出力だけを置き換えるフィルタの、2 つの部品を作る
  - テストで、2 つの方式のどちらでも、対象のタグ（開始と終了、大文字、空白つき）が置き換わり、対象外のタグ名と、エスケープしたテキストの中のタグに見える文字列が変わらないことが確かめられる
  - _Requirements: 10.5, 10.6_

- [ ] 5. 堅牢性と最終の検証
- [ ] 5.1 (P) 確保失敗の総当たりと文書のアロケータの使用を検証する
  - 組み込みの全型を含む木のバッファと書き出しの関数への出力、状態を持つフックの拡張、入れ子の出力のそれぞれについて、確保失敗の総当たりのテストを作る
  - テストで、すべての注入の回でメモリ不足が返り、リークがなく、バッファが元の長さであり、出力の確保がテスト用アロケータ（文書のアロケータ）だけを通ることが確かめられる
  - _Boundary: HtmlTests_
  - _Requirements: 1.5, 11.2_

- [ ] 5.2 (P) 深い木と計算量を検証する

  - テストで、深い木の出力が期待する長さとタグの数になり、時間がノードの数におおむね比例し、多数のスロットでも出力できることが確かめられる
  - _Boundary: HtmlTests_
  - _Requirements: 11.3, 11.4_

- [ ] 5.3 (P) HTML の出力のファジングターゲットを作る
  - 入力の先頭をオプション、残りを組み込みの型の木の組み立ての操作列として解釈し、確保の失敗を注入するアロケータで、バッファと書き出しの関数の両方へ出力するターゲットと種のファイルを作る
  - 異常終了とリークがなく、成功した出力が正しい UTF-8 で、安全モードでは生の HTML のリテラルと危険な URL が出力に現れないことを検査し、コーパスの再生のテストが成功する

  - _Requirements: 3.1, 3.2, 11.6_

- [ ] 5.4 全体の結合と規約の検証を行う
  - 静的と動的の両方の構成で全テスト（生成テスト、手書きのテスト、コーパスの再生、公開ヘッダの検査、エクスポートの検査、ライセンスヘッダの検査）を実行する

  - _Requirements: 11.1, 11.5_
