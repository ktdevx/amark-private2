# Implementation Plan

> この計画は、2026-11-27 の design（`syntax-tree` の「行 × 帯」と「中身の上の CST」のモデルに合わせた版）だけに基づく。前の版の tasks は引き継がない。
> 前提：`syntax-tree` は実装済み。`html-renderer` の `amark.core.html`（`amark_html_core_extension`）と `amark_test_html_gfm` の実装は 4.1 と 5.4 より前に要る。まだなければ、そのタスクの前で止めて報告する。
> 公開ヘッダは、宣言した関数をすべて実装していないとエクスポートの検査に通らない。各タスクは、自分が実装した関数だけを公開ヘッダに宣言して足す。同じ公開ヘッダに宣言を足すタスクは並列にしない。
> 定義の表、ラベルの正規化、case fold、文字参照の解読、タイトの判定、記録の検査を自前で作らない。`syntax-tree` の公開 API を使う。値は設定の関数でなく記録の関数で入れる。

- [ ] 1. 基盤：公開ヘッダ、ビルド、テストの生成手順
- [ ] 1.1 パーサの公開ヘッダとビルドとテストの登録の骨組みを作る
  - 4 つの公開ヘッダを、型、列挙、マクロ、スロットとブロックの振る舞いの構造体、組み込みの構文の役割の番号だけで作る（関数の宣言はまだ持たない）。スロットの種類の番号は既存の拡張のヘッダのものを使い、定義し直さない。
  - まとめのヘッダの 4 番目の組の位置に、4 つのヘッダを design の順で含める。
  - パースの層と組み込みの構文の層のソースを、design の File Structure Plan のファイル名で作り、ライブラリのソースの一覧に加える。10 の組み込みの拡張は、名前だけを持ちスロットのない記述子として各構文のファイルに置き、`src/syntax/` の中の共有ヘッダで宣言する。
  - パースと構文のテストのディレクトリを、Naos を使うターゲットと使わないターゲットを分けた形でテストの登録に加える。
  - 全構成（静的と動的、サニタイザ）でビルドが警告なしに通り、公開ヘッダの名前と順の検査、エクスポートの検査、ライセンスヘッダの検査を含む既存のテストがすべて通る。
  - _Requirements: 4.1, 4.10_

- [ ] 1.2 spec の例の形式からテストを生成する共有の手順を作る
  - spec.txt と同じ例の区切り（例の開始の行、`.` の行、終わりの行）を読み、名前とオプションの語、`→` のタブへの戻し、LF でつないだバイト列を扱い、例ごとに検査の関数を呼ぶ Naos のテストを生成する。検査の関数と含めるヘッダを引数で選べ、名前の重複と形の崩れを生成の失敗にする。
  - 生成の手順のテストのデータ（`---` と `===` の行、CR と NUL を含む例、名前のない例）で、生成したテストが受け取るバイト列と名前とオプションが期待どおりであることが、テストの生成の既存のテストの形で確かめられる。
  - _Requirements: 14.6_

- [ ] 2. 走査の関数
- [ ] 2.1 HTML ブロックの条件と HTML のタグの走査を実装する
  - 7 種類の開始の条件（段落を中断する場面では種類 7 を除く）、種類 1–5 の終わりの条件、属性と引用した値と改行を含みうる開始タグと終了タグの走査を、長さで境界を確かめる確保のない関数として公開する。
  - 走査のテストで、各種類の開始と大文字小文字、種類 7 の段落の中断、終わりの条件が同じ行にある場合、不完全なタグ、長さの境界での打ち切りが確かめられる。
  - _Requirements: 7.8_

- [ ] 2.2 リンクのラベル、宛先、タイトルの走査を実装する
  - ラベル（999 文字以下、エスケープされていない `[` なし、空白だけは不可。空白は空白とタブと LF と CR）、宛先（山括弧の形と、括弧の入れ子が 32 以下の形）、タイトル（3 つの引用符、空行なし）を、連続したバイト列の上の関数として公開し、括弧の深さとラベルの長さの上限をマクロで公開する。
  - 走査のテストで、999 文字と 1000 文字のラベル、空白だけのラベル、深さ 32 と 33 の括弧、空の山括弧の宛先、改行を含むタイトルと空行を含むタイトルが確かめられる。
  - _Requirements: 8.6, 8.7, 12.5_

- [ ] 2.3 値を綴る単位と中身の単位の走査を実装する
  - 連続したバイト列の上で、テキスト、エスケープ、文字参照（`syntax-tree` の解読の関数で確かめる）、置き換え（NUL と不正な UTF-8 の最大の部分）、改行の単位を印に従って返す関数を公開する。
  - 葉の中身の上で、それに加えて、配置済みの中身の部分の端がタブを切るときの空白をタブの残りとして返し、配置済みの仮想の改行と自由な中身の LF を改行として返す関数を公開する。
  - 走査のテストで、各単位の境界、印のない場合のエスケープと文字参照のテキストとしての扱い、不正な UTF-8 の列の区切り、`>\t\tfoo` の形の中身のタブの残り、自由な中身が確かめられる。
  - _Requirements: 2.3, 8.7_

- [ ] 3. パースのエンジンと入口
- [ ] 3.1 パースの文脈とパーサの寿命を実装する
  - 生成でオプション（大きさ、予約の印、深さの上限）と構文セットの凍結とスロット（大きさ、必須のコールバック、拡張ごとの状態のスロットの数）を検査し、ブロック構文を優先度で安定に並べ、受け皿を最後に置いたスロットの表を作る。構文セットは借りるだけにする。
  - 文書と空のソースを作り、feed で確定した行をエンジンに渡し、finish でソースを終えて残りの行と段階を実行して文書を返す。終了と失敗の後の呼び出しを状態の誤りにし、失敗したパーサの解放ですべてを解放する。一括のパースの入口を作る。この時点のエンジンは、空白だけの行を文書の空行に、それ以外の行をすべて取り手のない表記として文書に記録する。
  - 拡張の状態の確保と、構文セットの順の初期化と逆の順の後始末、文脈の文書とオプションと状態の取得、定義の検索（パースしている文書、断片では挿入先の文書も）を実装する。
  - 入口のテストで、一括と 1 バイトずつの逐次の入力（CR と LF の間を含む）で行の表とダンプが一致すること、空の入力、BOM、改行のない最後の行、凍結していない構文セットと未知のオプションの誤り、終了の後の誤り、2 つのスレッドでの 1 つの構文セットの共有、状態の初期化と後始末の順が確かめられる。
  - _Requirements: 1.1, 1.3, 1.4, 1.5, 1.6, 1.7, 1.8, 2.1, 2.4, 2.5, 2.6, 5.4, 5.5, 6.3, 11.3_

- [ ] 3.2 ブロックの開閉と照合のエンジンを実装する
  - 根から末端までの開いたブロックのスタックを持ち、外側から継続の条件で照合し、開始を優先度の順に試し（段落の類の現在のコンテナでは中断の印のない構文を飛ばす）、行を使い切る結果と行の残りでの開始の繰り返しを扱う。再帰を使わない。
  - ブロックを開く関数（照合できなかったブロックと受け入れられない祖先を閉じてから足し、行の範囲を設定する）を公開し、閉じるときは子から順に閉じの処理とデータの後始末を呼び、入力の終わりですべてを閉じる。
  - 現在の行の問い合わせ（行の番号とバイト、位置、字下げ、最初の空白でない位置、空行かどうか、現在のコンテナと末端、すべて照合したか、遅延継続になりうるか、開いたブロックのデータ、深さ）を公開する。行のない文脈では行の問い合わせが行なしを返す。
  - ブロックの構文の API のテストで、テスト用のコンテナと葉の構文により、照合と閉鎖の順、入れ子の開始（リストと項目の形）、ブロックごとのデータと後始末、中断の印と開始の判断、受け入れられない祖先の閉鎖、コールバックの失敗の伝播が、木のダンプと呼び出しの記録で確かめられる。
  - _Requirements: 3.1, 3.2, 3.3, 3.6, 3.7, 4.2, 4.3, 4.4, 4.9, 12.4_

- [ ] 3.3 帯と葉自身の表記と中身の記録、遅延継続、受け皿を実装する
  - 帯の列を進める関数と持ち主を決めずに進める関数、位置のバイトとタブの残りと持ち主の決まった列の問い合わせ、持ち主の決まった列からの葉自身の表記と中身の部分の記録（対象のブロックの行の範囲を現在の行まで広げる。空のトークンは記録せず、空の中身の部分は空の行として記録する）、行の後で閉じる求めを公開する。呼び出しの種類と行の有無で使えない関数を状態の誤りにする。
  - 最終の列のコンテナへの帯（開いた行は最初の行の印）、遅延継続（照合できなかったコンテナに外側の帯の終わりの列で LAZY の帯）、受け皿、行の受け入れ、取り手のない表記を design の順で行う。深さの上限ではコンテナの印の構文を試さず、印のない構文が上限を超えて開いたら上限の誤りにする。この時点では空行を、その行の最も内側の開いたコンテナの空行としてすぐ記録する（3.6 で保留に置き換える）。
  - ブロックの構文の API のテストで、テスト用の構文から、タブを切る帯と表記と中身、遅延継続の帯の列、深さの上限で残りが受け皿の葉になること、受け皿のない構文セットの取り手のない表記、誤用の状態の誤りが、ロスレス性の検証とダンプで確かめられる。
  - _Requirements: 2.2, 3.4, 4.5, 9.2, 9.3, 12.1, 12.2_

- [ ] 3.4 インラインの段階と単純な委譲先を実装する
  - インラインを受け入れる中身を持つ葉を、文書の順に再帰なしにたどって委譲先へ渡し、委譲先の失敗でパースを止める。オプションの委譲先がなければ既定の委譲先を、1 か所の内部関数で選ぶ（この時点では単純な委譲先）。
  - 単純な委譲先を公開する：中身の各行をテキストのノードに、行の間をソフトブレークのノードにし、ノードを先に足してからトークン（テキスト、置き換え、タブの残り、改行）を記録して中身の全体を覆う。配置済みと自由な中身の両方を扱う。
  - インラインの段階のテストで、テスト用の構文で作った段落の類の葉について、委譲の順、渡す中身、文脈の取得、単純な委譲先の木とトークンがロスレス性の検証に通ること、自由な中身の葉、委譲先の失敗の伝播が確かめられる。
  - _Requirements: 6.1, 6.2, 6.4, 6.5, 6.6_

- [ ] 3.5 パースの検査の補助を作る
  - 一括でパースし、不変条件の検査、ロスレス性の検証、根を元の表記のまま出せることを確かめ、1 バイトずつと CR と LF の間を含む区切りの逐次の入力で、配置、綴り、style、行の表を含むダンプが一致することを確かめてから、一括の文書を返す補助を、Naos を使うテストのライブラリとして作る。委譲先の指定がなければ単純な委譲先を明示して使う。
  - 補助のテストで、テスト用の構文の文書が通ること、わざと抜けを作るテスト用の構文で検証の不整合が理由とともに報告されることが確かめられる。以後のパースのテストはこの補助を通す。
  - _Requirements: 14.3, 14.5_

- [ ] 3.6 保留の空行の解決を実装する
  - 葉が取らない空行を保留し、空でない帯だけをその場で記録する。次の空でない行の置き場所が決まった時点か入力の終わりで、まだ開いているか空でない帯を持つブロックを含むものとし、後に中身が続く葉にはその行を再生して渡し、そうでなければ含むコンテナに長さ 0 の帯を、含む最も深いブロックに空行を記録する。
  - 3.3 の仮の空行の記録をこの仕組みに置き換える。
  - 空行のテストで、テスト用のコンテナと後に続くときだけ空行を取る葉の構文により、文書・コンテナ・通り抜けのブロックが空行の持ち主になる場合、末尾の空行が範囲に入らないこと、項目のように持ち主を決めずに進めた列が空行に含まれることが、検査の補助を通して確かめられる。
  - _Requirements: 3.5, 9.4_

- [ ] 3.7 段落の類の操作を実装する
  - 段落の消費のスロットの実行（段落の類の葉が閉じるときと、求められたとき）、行の切り出し（構造の表記と中身の部分を写して新しい葉を前に置き、消費の後に 1 回で行を除き、行が残らなければ葉を除く）、すべての行を引き継ぐ別の型への置き換え、末尾の行の解放を公開する。段落の類でない葉と、消費の外での切り出しを誤りにする。
  - ブロックの構文の API のテストで、テスト用の消費と構文により、切り出しの後の段落と新しい葉の記録、すべての行の切り出しで段落が残らないこと、置き換えの後も開いたままの葉、末尾の行の解放と記録し直しが、ロスレス性の検証に通ることが確かめられる。
  - _Requirements: 4.6, 4.7, 4.8_

- [ ] 3.8 後処理の段階と、型の置き換えと中身の被覆の補助を実装する
  - すべてを閉じた後に、インラインの前の後処理、インラインの段階、インラインの後の後処理を、それぞれ構文セットの順で実行し、失敗でパースを止める。
  - 中身を持たないブロックを、行の範囲と帯と空行とレイアウトのトークンを写した別の型に置き換えて子を移す補助と、葉の中身の全体を中身の単位のトークンで覆う補助を公開する。失敗したら何も変えない。
  - 後処理のテストで、段階と構文セットの順、失敗の伝播、置き換えと中身の先頭の削りの後のロスレス性と根を元の表記で出せること、被覆の補助で覆った葉の値が中身から導いた値と一致することが確かめられる。
  - _Requirements: 5.1, 5.2, 5.3, 9.7_

- [ ] 4. CommonMark のブロック構文
- [ ] 4.1 CommonMark の構文セットの構築と、構文ごとのケースの登録を作る
  - `amark.core` の後に組み込みの HTML 出力の拡張、10 のブロック構文の拡張を design の表の順に足す構築関数（凍結しない）、利用者の構文セットに同じ規則で足す関数（失敗で変えない）、CommonMark でのパース（文書が構文セットを所有）、拡張の数と添え字と名前による取得を公開する。`html-renderer` の実装が要る。
  - 検査の補助に、CommonMark の構文セットでパースしてダンプを期待値と比べる例の検査の関数（ダンプの印、最後の改行の除去、CRLF と CR への変換のオプションの語）を足す。
  - 構文ごとのケースのデータのファイルを 10 個と組み合わせのファイルを作り（それぞれ空の入力の例 1 つから始める）、共有の生成手順で登録する。
  - 構文セットのテストで、組み立ての順、凍結しないこと、利用者の構文セットへの追加の位置と失敗、HTML の出力ができること、拡張の名前による取り除きと置き換えの後に構文セットが凍結できることが確かめられる。
  - _Requirements: 1.2, 3.8, 7.2, 7.3, 7.4, 14.1_

- [ ] 4.2 段落（受け皿）を実装する
  - 受け皿の構文と段落の類の振る舞い（空行で終わり、遅延継続を受ける）を実装し、各行の字下げを表記に、最初の空白でない文字から行の終わり（末尾の空白を含む）を中身にする。
  - 組み込みの構文が共有する字下げと空白の補助を、`src/syntax/` の中の共有ヘッダに用意する。4.3–4.9 は共有ヘッダを変えない。
  - 段落のケースで、複数行の段落、各行の先頭の空白、最後の行の末尾の空白が中身に残ること、取り除いた構文の行が段落になることが、配置と綴りを含むダンプで確かめられる。
  - _Requirements: 6.2, 7.1, 9.6, 11.1_

- [ ] 4.3 (P) 引用を実装する
  - 字下げ、`>`、後の空白 1 列（タブを切ってよい）を帯にする開始と継続を実装する。段落を中断でき、コンテナの印を持つ。
  - 引用のケースで、`>` だけの行が引用の空行になること、遅延継続の帯、`>\t\tfoo` のタブの分け合い、入れ子の引用が、配置を含むダンプとロスレス性の検証で確かめられる。
  - _Depends: 4.1, 4.2_
  - _Boundary: Builtins（block_quote）_
  - _Requirements: 7.1, 9.2, 9.3_

- [ ] 4.4 (P) リストと項目を実装する
  - 記号の走査、同じ種類のリストへの項目の追加か新しいリスト、段落を中断するときの制限（空の項目、1 以外で始まる順序付き）、記号の後の空白の規則（5 列以上で 1 列、後が空白だけで 0 列）による最初の行の帯を実装する。
  - 項目の継続を cmark の順（字下げが幅以上なら幅だけ帯、空行では帯を空にして幅か字下げの分だけ持ち主を決めずに進める、子がなければ空行で終わる）で実装する。種類、開始番号、記号か区切りの style を記録し、タイトは記録しない。
  - リストのケースで、タイトとルーズの例（項目の間の空行、項目の中の子の間の空行、入れ子のリスト、末尾の空行）のタイトの値が cmark と一致すること、空の項目と記号の後が空白だけの行、最初の行の印、遅延継続が確かめられる（ほかの構文との組み合わせは 5.1）。
  - _Depends: 4.1, 4.2_
  - _Boundary: Builtins（list）_
  - _Requirements: 7.1, 7.5, 7.6, 7.7, 9.5_

- [ ] 4.5 (P) thematic break と ATX 見出しを実装する
  - thematic break の行を記号の連続と空白の連続の表記で覆い、文字と数と間の空白の style を記録する。ATX 見出しの字下げ、開きと閉じの記号、空白を表記にし、見出しの文字列を中身にし、レベルと形と閉じの記号の有無を記録する。
  - ケースで、空の見出し、閉じの記号だけの見出し、閉じの記号に見えるが文字列の一部の場合、間に空白のある thematic break、段落の中断が確かめられる。
  - _Depends: 4.1, 4.2_
  - _Boundary: Builtins（thematic_break、atx_heading）_
  - _Requirements: 7.1, 7.5, 7.6, 9.6_

- [ ] 4.6 (P) インデントされたコードとフェンスのコードを実装する
  - インデントされたコード：遅延継続になりうるときは開かず、4 列の字下げを表記にし、空行は後に中身が続くときだけ中身にする。閉じるときに中身の全体を覆う。
