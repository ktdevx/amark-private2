# Implementation Plan

- [ ] 1. 基盤：公開ヘッダ、上流の追加、テストの補助
- [ ] 1.1 パーサの公開ヘッダと内部ヘッダを宣言し、ビルドとテストの登録に組み込む
  - 設計の契約どおりに、パーサ、ブロック構文、走査、CommonMark、文字参照の 5 つの公開ヘッダを、前方宣言を 1 か所に置いた依存の順で作り、すべての関数・型・定数（性質の印、開始と継続の結果、スロットの構造体、役割の番号と優先度、深さの既定値と上限、宛先の括弧の入れ子の上限 `AMARK_SCAN_MAX_LINK_PAREN_DEPTH`（32）、走査のヘッダのバイト列の HTML のタグの走査と HTML ブロックの開始と終わりの条件の関数と種類の範囲の定数、パーサの失敗の例外の注釈、構文セットの所有権が生成の成功で文書へ移ることの注釈、インラインの入力を持つノードを後処理で解放するときの約束の注釈）を宣言する
  - ブロックのヘッダのエンジンの役割の定義の前に、役割の番号の範囲の注記（組み込みのブロック 0x0001–0x00FF、組み込みのインライン 0x0100–0x01FF、ブロックのエンジン 0xFF00–0xFF0F、インラインのエンジン 0xFF10–0xFF1F、予約 0xFF20–0xFFFF）を書き、エンジンの役割をブロックのエンジンの範囲の中で定義する
  - 拡張のヘッダの、`syntax-tree` が置いたスロットの種類の範囲の表の `block-parser` の節の下に、この spec のスロットの種類の番号（0x0100–0x0103）を追記し、全体をまとめるヘッダに 5 つのヘッダを `foundation` の正準の順（`amark.h` の include の順の規則）のそれぞれの位置に追加する
  - パースの内部ヘッダに、パーサ、パースの文脈、ブロックの文脈、開いているブロック、ノードごとの内部の表の要素、行の構造体と内部関数を宣言する
  - 設計の File Structure Plan の `src/parse/`、`src/syntax/`、`src/runtime/entity.c` をライセンスヘッダつきで作ってライブラリのソースに加え、`tests/parse/` と `tests/syntax/` をテストの構成に加える
  - 構文ごとのファイルには、設計の名前を持ちスロットがまだ空の拡張と、その取得の関数を置く（各構文のタスクがスロットを埋める。並行して作業できるように、構文のファイルどうしは互いを参照しない）
  - 静的と動的の両方の構成で警告なしにビルドでき、公開ヘッダの単独コンパイルの検査（C と C++）が新しいヘッダについても成功する
  - パーサのヘッダでは、構文セットを `const` で借りる生成と、非 `const` の構文セットの所有権を受け取る別の生成の入口を宣言し、所有権の印のフラグは置かない（`const` を外すキャストを使わない）
  - _Requirements: 1.9, 4.1, 4.9, 7.7, 9.5, 9.7, 12.6_

- [ ] 1.2 構文セットの所有権を文書に渡す上流の操作が、パーサの使い方に合うことを確かめる（上流の変更）
  - 上流の操作は `syntax-tree` の spec（1.10、1.11）に反映済みで、`syntax-tree` のタスク 3.4 が実装する。この spec では実装せず、パーサが頼る契約（生成の最後に呼ぶ、確保をしない、拒否のときに所有権が呼び出し側に残る）を確かめる
  - 公開 API だけを使う契約のテストを置き、文書が使っているヒープの構文セットの受け渡しが成功して文書の解放で解放されること（テスト用アロケータのブロック数が 0）、静的な構文セット・文書が使っていない構文セット・2 回目の受け渡しが引数の誤りになり、所有権が呼び出し側に残ることを確かめられる
  - _Boundary: ParseTests_
  - _Requirements: 1.2, 11.3_

- [ ] 1.3 子をまとめて全か無かで取り込む上流の操作が、断片のパースの使い方に合うことを確かめる（上流の変更）
  - 上流の操作は `syntax-tree` の spec（4.10、4.11）に反映済みで、`syntax-tree` のタスク 5.5 が実装する。この spec では実装せず、断片のパースが頼る契約（根を取り込み元の親にできる、検査と確保をつなぎ込みの前に終える、記録の規則）を確かめる
  - 公開 API だけを使う契約のテストを置き、別の文書の根の 2 つの子の取り込みでソースが 1 つだけ増えること、包含に反する子があると何も挿入されず引数の誤りになること、子のない親の取り込みが何もせず成功すること、追跡中は親に子の変更・各ノードに位置の変更が記録されることを確かめられる
  - _Boundary: ParseTests_
  - _Requirements: 10.1, 10.2, 10.4, 10.5_

- [ ] 1.4 パースの検査の補助と、データ駆動のテストの生成手順を作る
  - 一括でパースして、構文トークンの被覆の検証、木の不変条件の検査（INTERNAL のときだけ）、1 バイトずつ・2 分割・ランダムな区切りの逐次の入力のダンプと一括のダンプの一致を確かめ、通れば一括の文書を返し、失敗なら診断を表示して誤りを返す関数を、INTERFACE ライブラリとして作る（構文セットを指定しないときは、作ったテスト用の構文セットを返す文書に所有させる）
  - その関数の結果を確かめ、期待するダンプとの一致を照合して文書を解放するマクロを、関数の上に置く
  - この補助は Naos を使うので、`tests/CMakeLists.txt` では INTERFACE ライブラリ `amark_test_parse` の定義と `add_subdirectory(syntax)` を `if(AMARK_BUILD_TESTS)` の中に置き、`add_subdirectory(parse)` は `tests/` の中で条件なしに加える（`foundation` の規則 7.7。`tests/parse/` の中の Naos を使うテストは `if(AMARK_BUILD_TESTS)` の中に置く）
  - spec.txt と同じ区切りの形式のデータファイルから補助を呼ぶテストを生成する共有のスクリプトを `tests/support/gen_examples.cmake` として作り、設計の「`gen_examples.cmake` の契約」（`→` はタブ、見出しの行が節の名前、テストの名前 `ex<4 桁の番号>_<節>`、開始の行の `n=`、基本の ARGS の `EXPECT=dump` と `DUMP_FLAGS=`、`FACTORY` / `CHECK` / `EXPECT=html` の予約、未知の名前と形式の誤りの構成の失敗）どおりに、NUL と CR を失わずに埋め込む。`inline-parser` が後で追加だけで拡張できるよう、基本の経路の出力を 1 か所で作る
  - `tests/syntax/data/` のすべてのデータファイルを構成時に集めて登録し、構文のタスクがデータファイルを足すだけでテストが増える形にする（テストの構成のファイルを各タスクが編集しない）
  - 構文セットの指定がないときに使う、テスト用の構文セット（`amark.core` とすべての構文の拡張。出力の拡張は含まない）を作る補助を置く
  - 生成の自己テスト用の小さなデータ（`tests/support/data/gen_examples_selftest.txt`。NUL、CR、タブ、`n=`、複数の見出しを含む）から生成したテストがビルドされて実行され、予約した名前・未知の語・閉じのない例で構成が失敗することを確かめられる
  - _Boundary: ParseCheck, SyntaxTests_
  - _Requirements: 14.1, 14.3, 14.5, 14.6_

- [ ] 2. 文字データ
- [ ] 2.1 (P) 完全な Unicode の case fold の表と関数を追加する
  - foundation の生成スクリプトに `CaseFolding.txt`（状態 C と F）の読み取りを足し、符号位置の昇順の表を生成してリポジトリに入れ、照合（`--check`）の対象に加える
  - 符号位置を 1–3 個の符号位置に畳み込む関数を、ASCII の早道と二分探索で実装する
  - テストで、`ẞ` が `ss` に、ASCII の大文字が小文字に、対応のない文字とサロゲートが自身になること、表の版が foundation の Unicode の版と一致することを確かめられる
  - _Boundary: CaseFold_
  - _Requirements: 8.3_

- [ ] 2.2 (P) 文字参照の表と解読の関数を追加する

  - 先頭の名前付き・10 進・16 進の文字参照を解読して消費したバイト数を返し、数値の 0、サロゲート、範囲外を U+FFFD にし、桁数の上限（10 進 7、16 進 6）を超えるものと未知の名前を文字参照としない関数を実装する
  - テストで、代表の名前（2 つの符号位置になるものを含む）、セミコロンのない名前、未知の名前、数値の境界と桁数の境界が期待どおりになる
  - _Boundary: Entity_
  - _Requirements: 8.7_

- [ ] 3. テキストの入力、ラベル、走査
- [ ] 3.1 (P) 区間の並びのテキストを実装する
  - 区間の追加、全体の長さ、区間の数と取得、論理的な位置からの連続するバイト列・1 バイト・ソース上のオフセットの取得、区間ごとの仮想の空白の列の問い合わせを実装する
  - 区間の追加は償却定数時間、位置の検索は区間の二分探索で行う
  - テストで、隙間のある 3 つの区間の論理的なテキストの各位置が正しいソースのオフセットに対応し、範囲外の位置が「なし」を返すことを確かめられる

  - _Requirements: 6.2_

- [ ] 3.2 ラベルの正規化と、正規化したラベルで引ける表を実装する
  - 前後の空白の除去、内部の空白（空白、タブ、改行）の 1 つの空白への置き換え、case fold、不正な UTF-8 と NUL の U+FFFD への置き換えで正規化する（エスケープは解かない）
  - キーを複製して持ち、最初の登録だけを残す AVL 木の表（追加、検索、数）を実装する
  - テストで、`ẞ` と `SS` と ` ss ` が同じキーになること、2 回目の登録が「追加しない」を返して値が最初のままであること、10 万件の挿入と検索の後も木の高さが対数に収まることを確かめられる
  - _Depends: 2.1_
  - _Requirements: 2.5, 8.3, 8.4, 8.6_

- [ ] 3.3 リンクのラベル・宛先・タイトルの走査を実装する
  - 区間の並びの上で、CommonMark 0.31.2 の規則どおりにラベル（999 文字以下、エスケープされていない `[` を含まない、空白以外を含む）、宛先（山括弧の形と、括弧の釣り合う空白なしの形）、タイトル（3 種類の囲み、空行を含まない）を走査し、確保せずに終わりの位置を返す
  - 区間の境目（行の境目）をまたぐタイトルとラベルを扱う
  - 括弧の釣り合う形の宛先で、エスケープされていない括弧の入れ子の深さを数え、公開した上限（32）を超えた時点で宛先としない（深さの数は上限で止まり、走査は 1 回の前進で終わる）
  - テストで、各規則の成立と不成立の境界（1000 文字のラベル、釣り合わない括弧、深さ 32 の括弧の成立と 33 の不成立、エスケープされた括弧が深さに数えられないこと、山括弧の形に上限がないこと、空行を含むタイトル、エスケープされた囲みの文字、区間をまたぐタイトル）が期待どおりになる
  - _Requirements: 8.7, 12.6_

- [ ] 3.4 (P) HTML のタグの走査と HTML ブロックの条件を、バイト列と区間の並びで共有する 1 つの実装として作る
  - 連続したバイト列と区間の並びの論理的な位置のどちらからも読める内部の読み取りの上に、タグの名前、属性の名前と 3 種類の値、空白と改行、自己終了の `/>` を CommonMark 0.31.2 の規則どおりに走査する内部の関数を 1 組だけ作り、区間の並びの版とバイト列の版の開始タグと終了タグの走査を、それに読み取りを渡す薄い包みとして公開する
  - 同じ内部の走査の上に、HTML ブロックの 7 種類の開始の条件（字下げを除いた行、種類 1 と 6 のタグ名は大文字小文字を区別しない、種類 7 は完全なタグの後に空白だけで、段落を中断する場面では不成立）と、種類 1–5 の終わりの条件（種類 6・7 と範囲外は不成立）を、バイト列の上の公開の関数として作る。どれも確保せず、1 回の前進で終わる
  - テストで、属性のない・ある・引用符の値・改行をまたぐタグ、不正なタグの名前、閉じない引用符、各種類の開始の条件の成立と不成立の境界、中断の場面での種類 7、各種類の終わりの条件、開始と終わりが重なる `<!-->` が期待どおりになり、同じ内容の 1 区間・行で分けた区間・バイト列に対してタグの走査の両方の版が同じ真偽と終わりの位置を返す
  - _Boundary: Scanners_
  - _Depends: 3.1_
  - _Requirements: 7.7, 7.8, 8.7_

- [ ] 4. パースの文脈
- [ ] 4.1 拡張の状態、トークンの記録の補助、テキストの解読を実装する
  - パースの状態のスロットごとに領域を 0 で埋めて確保し、構文セットの順に初期化し、途中の失敗では初期化済みのものを逆順に破棄し、拡張から自分の領域を引けるようにする
  - トークンの追加の補助と、範囲を正しい UTF-8（テキスト）と NUL・不正な UTF-8（置換）に分けて記録し、値を U+FFFD に置き換えてバッファに追加する補助を実装する
  - 区間の並びの範囲を、エスケープ（ASCII の句読点の前だけ）、文字参照、改行（値は LF）、その他に分けて記録しながら解読する補助を実装する（区間の間の隙間は記録しない）
  - リンク参照定義の表をパースの文脈に持たせ、文書・オプション・表を引けるようにする
  - テストで、`a\*b&amp;c\0\xff` を含む範囲のトークンの並び（種類と位置）と値、区間をまたぐ範囲の改行のトークン、状態の初期化の失敗で破棄が逆順に呼ばれることを確かめられる
  - _Depends: 2.2, 3.1, 3.2_
  - _Requirements: 2.3, 2.5, 5.3, 6.3, 8.5, 8.7_

- [ ] 4.2 インラインの入力の登録と、後処理の実行を実装する
  - ノードを鍵とする内部の表に、ノードごとのインラインの入力（区間の並び）を持ち、区間の追加、取得、先頭の指定した長さを別のノードへトークンとして記録して除く操作、破棄、別のノードへの移動を実装する
  - 後処理のスロットを、指定した段階のものだけ構文セットの順に実行し、失敗をそのまま返す
  - テストで、先頭の消費が入力の長さを超えると引数の誤りになること、消費した部分のトークンが指定したノードに記録されて入力が短くなること、2 つの段階の後処理が構文セットの順に実行されることを確かめられる
  - _Requirements: 4.7, 5.1_

- [ ] 5. ブロック構文エンジン
- [ ] 5.1 入力のチャンクから行を切り出す処理を実装する
  - LF、CR、CRLF で行を切り出し、チャンクの末尾の CR を次のチャンクを見るまで保留し、先頭の BOM を 3 バイトが揃うまで判定を保留して行の始まりから外し、終了の指示で改行で終わらない最後の行を返す
  - 行の内容はソースを参照し、複製しない
  - テストで、改行コードの混在、境目で分かれた CRLF と BOM、空の入力、改行で終わらない最後の行のそれぞれで、どの区切り方でも同じ行の並びになる
  - _Requirements: 1.3, 2.1, 2.4, 2.6_

- [ ] 5.2 ブロックの文脈の、行の位置と列の参照と、消費の操作を実装する
  - バイトの位置と列（4 列のタブストップ、1 行目は BOM の後から）と、途中まで消費したタブの残りの列を持つ行のカーソルを実装し、インデント、最初の非空白、空行かどうかの問い合わせを提供する
  - 列の数だけ空白とタブを消費する操作（タブの一部の消費では部分的なタブのトークンを作り、残りを次へ回す）、バイト数の消費、行末までの消費、改行の消費を、指定したノードへの記録つきで実装する
  - 範囲外の消費、空白以外に及ぶ列の消費、閉鎖の中での行の操作を、位置を変えずに拒否する
  - テストで、`>\t\tfoo` の形の行で、1 列・3 列・4 列の消費のトークン（部分的なタブの列の内訳）と列の値が期待どおりになる
  - _Requirements: 2.2, 4.6_

- [ ] 5.3 開いているブロックの鎖、ブロックを開く・閉じる操作、ブロックのデータ、空行の印を実装する
  - 鎖の要素（ノード、構文、データ、空行の印、開いた行）を配列で持ち、ブロックを開くときに照合できなかったブロックを閉じ、親が受け入れられるまで閉じながら上へたどってからノードを付ける。根まで受け入れられなければ引数の誤り
  - 1 つの開始の中で入れ子に開けるようにし、ブロックのデータを 0 で埋めて確保してパースの終わりまで保ち、終わりに破棄の関数を呼ぶ
  - 内側から順に閉鎖の関数を呼ぶ閉鎖、最後に照合したブロックと最も内側のブロック、構文、データ、空行の印の取得と上書き、行の番号の問い合わせを実装する
  - テストで、受け入れられない親を閉じながらたどる様子（閉鎖の呼び出しの順）と、入れ子に開いた 2 つのブロックのデータが別々に保たれることを確かめられる
  - _Requirements: 3.3, 3.5, 4.3_

- [ ] 5.4 1 行の処理の 5 段階と、終了時の閉鎖を実装する
  - 外側からの照合（閉鎖して行を終える結果を含む）、行をそのまま受け入れる葉での開始の省略、（優先度、構文セットの順）に並べた開始の候補の試行（きっかけの文字の集合による省略、中断中の候補の絞り込み、コンテナを開いた後の試し直し、副作用のある「成立しない」の拒否と段落の先頭の消費だけの許容）を実装する
  - 遅延継続（照合できなかった各コンテナへの印の記録と、最も内側の段落の類への行の追加）、照合できなかったブロックの閉鎖、空行のトークンの記録と空行の印の規則、葉への行の追加、受け皿による段落の類の開始、受け皿がないときの残りの記録を実装する
  - 深さが上限に達したらコンテナの開始を試さず、コールバックの失敗で処理を止め、終了の指示で鎖のすべてを内側から閉じる。再帰を使わない
  - 照合・開始の試行・記録したトークンの内部のカウンタを持たせる
