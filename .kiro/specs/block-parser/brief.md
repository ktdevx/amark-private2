# Brief: block-parser

## Problem
Markdown のテキストから構文木を作るには、まずブロック構造（引用、リスト、コードブロック、見出し、段落など）を確定させる必要がある。Amark では、CommonMark のブロック構文も、利用者の拡張と同じ公開 API の上に乗せる。そのため、汎用のブロック構文エンジンと、拡張から使えるブロック構文 API が必要になる。さらに、ロスレスな書き戻しのために、パースの途中で元の表記を構文トークンとして記録しなければならない。

## Current State
まだ存在しない。`syntax-tree` のノードモデル、構文トークン、拡張レジストリの上に作る。

## Desired Outcome
- パーサの公開 API がある。
  - 構文セットとオプションの指定
  - 文字列全体のパースと、ストリームでの逐次の入力（feed してから finish する）
- CommonMark の行単位のブロック解析アルゴリズム（開いているコンテナとの照合、新しいブロックの開始、遅延継続、ブロックの閉鎖）を、汎用のエンジンとして実装する。
- 公開のブロック構文 API で、次のことができる。
  - 新しいブロックの開始条件と継続条件の定義
  - 段落を中断できるかどうかの指定
  - 閉じた後の処理
  - 既存のブロックを別のブロックとして解釈し直すこと（表のように、段落を後から表に変える）
- 文書の後処理フックがある。脚注やタスクリストのように、パースが終わった後に木を書き換える処理に使う。
- CommonMark の全ブロック構文と、リンク参照定義を、組み込み拡張として実装する。
  - 全ブロック構文：thematic break、ATX 見出し、setext 見出し、インデントされたコードブロック、フェンスで囲まれたコードブロック、HTML ブロックの 7 種類、リンク参照定義、段落、空行、引用、リスト項目、リスト
- 構文トークンを記録する。記録するのは、コンテナの接頭辞、マーカー、インデント、空行、改行コード、末尾の空白など、往復でバイト単位で同じ出力を得るために必要な情報すべてである。
- インラインの解析は、`inline-parser` が提供するエンジンへ委譲する。この委譲のインタフェースはこの spec が定義する。

## Approach
- 構文定義駆動のエンジンとする。中核の処理は、登録されたブロック構文の記述子を優先度順に試すだけにし、個別の構文の知識を持たない。
- 前処理（タブの展開、NUL 文字の置換、改行コードの正規化）は、構文トークンが元の表記を復元できる形で行う。
- リンク参照定義の表（ラベルの正規化：大文字小文字の畳み込みと空白の正規化）は、`inline-parser` と共有する。
- パースの深さと計算量に上限を設ける。病的な入力でも二次以上の計算量にならないことを、ファジングとベンチマークで確認する。

## Scope
- **In**：
  - パーサの公開 API と、構文セットやオプションの指定
  - ブロック構文エンジン、公開ブロック構文 API、文書の後処理フック
  - CommonMark の全ブロック構文とリンク参照定義
  - ブロックの構文トークンの記録
  - インラインへの委譲のインタフェース
  - ブロックのファジングターゲット
- **Out**：
  - インラインの解析（`inline-parser`）
  - CommonMark spec 全体での 100% の判定（インラインが揃ってから `inline-parser` で行う）。この spec では、木のダンプで期待値と照合するテストと、spec のブロックの章の例を使ったテストで検証する。

## Boundary Candidates
- ブロック構文エンジン（汎用）
- CommonMark のブロック構文の定義（組み込み拡張）
- 構文トークンを記録する処理

## Out of Boundary
- インライン構文、区切り文字の処理
- レンダリング

## Upstream / Downstream
- **Upstream**：`syntax-tree`
- **Downstream**：`inline-parser`、`markdown-renderer`（構文トークンを使う）、利用者の拡張

## Existing Spec Touchpoints
- **Extends**：`syntax-tree` の拡張記述子に、ブロック構文のスロットと後処理のスロットを足す。構文トークンのモデルに不足が見つかったら、`syntax-tree` に戻って更新する。
- **Adjacent**：`inline-parser`（委譲のインタフェースとリンク参照定義の表を共有する）

## Constraints
- 次の GFM 相当のフックが、拡張だけで実装できなければならない。受け入れテストは `inline-parser` の検証用拡張で行う。
  - 表：段落の解釈し直しと、行単位の継続
  - 脚注の定義：コンテナブロックと、定義の表
  - タスクリスト：リスト項目の後処理
- 入力は UTF-8 とする。不正なバイト列があってもクラッシュせず、置換文字などで処理を続ける。
