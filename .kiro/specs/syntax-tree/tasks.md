# Implementation Plan

- [x] 1. 基盤：公開ヘッダ、内部の構造、ビルドへの組み込み
- [x] 1.1 構文木の公開ヘッダと内部ヘッダを宣言し、ビルドとテストの登録に組み込む
  - 設計の「公開ヘッダの構成」に従い、ノード、文書、構文トークン、走査、ダンプ、拡張の 6 つの公開ヘッダを、前方宣言を 1 か所に置いた依存の順で作り、設計のすべての関数・型・定数（組み込みの型の識別子、編集の記録のビットと「未知のビットは内容の変更とみなす」注釈、トークンの種類と印、スロットの番号の範囲（Amark 1–255、利用者 256 以上）の定数と、下流の spec が定める種類の通し番号の一覧（block-parser 1–4、inline-parser 5–10、html-renderer 11–12、markdown-renderer 13–14）を記した注記、`const` でない引数をとる構文セットの所有の受け渡し、子をまとめた取り込み）を宣言する
  - 全体をまとめるヘッダに、6 つのヘッダを、foundation の design が定める正規の include の順の「木のヘッダ」の位置に、設計の順で追加する
  - 内部ヘッダに、文書・ノード・内部のトークン・ソースの構造体、構文セットの内部の構造、モジュール間の内部関数の宣言を置く
  - 設計の File Structure Plan の `src/tree/` の各ソースをライセンスヘッダつきで作ってライブラリのソースに加え、`tests/tree/` のテストのディレクトリをテストの構成に加える
  - 静的と動的の両方の構成でビルドが警告なしに成功し、foundation の公開ヘッダの単独コンパイルの検査（C と C++）が新しい 6 つのヘッダについても成功する
  - _Requirements: 10.1, 10.2_

- [x] 2. 拡張のレジストリ
- [x] 2.1 組み込みのノード型の記述子と、それをまとめた core の拡張を定義する
  - 19 の型（リンク参照定義を含む）の記述子を、設計の表どおりの識別子・名前・ブロック/インライン・分類・受け入れる分類・リテラルの方式・型のデータで定義する
  - 文字列の属性を持つ型（code_block、link、image、link_definition）に、公開の確保の関数（グローバルのアロケータ）で文字列を管理する解放・複製・比較の関数表を与え（組み込みの属性のダンプは dump.c が書くので、組み込みの型は `dump` を持たない）、list の比較では開始番号を順序付きのときだけ比べる
  - code の空のリテラルを拒否するリテラルの検査を与える
  - 19 の記述子を識別子の順に持ち、スロットを持たない core の拡張を、拡張と同じ記述子の形式で定義する
  - 内部用のテストで、表の各行（名前、識別子、分類、葉かどうか、リテラルの方式）が設計の表と一致することを確かめられる
  - _Requirements: 2.1, 2.4, 2.5, 8.1_

- [x] 2.2 構文セットの生成・変更・凍結・問い合わせを実装する
  - 生成時に core の拡張を先頭に置き、core の削除・置換・前への挿入を拒否する
  - 追加・名前を指定した挿入・削除・同じ位置への置換を、記述子の検査（名前の文字、拡張の型の名前の `.`、ブロック/インラインのどちらか一方、既知のリテラルの方式、データの大きさの上限、スロットの番号と大きさ）と名前の重複の検査つきで行い、失敗時は構文セットを変えない
  - 凍結で型の名前の重複を検出し、拡張の型に 256 から順に識別子を割り当て、名前の索引とスロットの種類ごとの索引を作る。凍結後の変更は不正な状態を返す
  - 名前・記述子・識別子の相互の検索、スロットの種類ごとの順の列挙、凍結していない複製、core だけを持つ静的な凍結済みの構文セットを提供する
  - 静的な core の構文セットに、所有の受け渡しで拒否するための静的の印を持たせる
  - テストで、順序の操作、拒否の規則、同じ構成での識別子の一致、凍結の前後の振る舞い、利用者の範囲の番号を含むスロットの列挙、複製が凍結されていないこと、静的な構文セットの解放が何もしないこと、spec ごとのスロットの種類の範囲が重ならず Amark の範囲に含まれることを確かめられる

- [x] 3. 文書とノードの中核
- [x] 3.1 編集の記録の仕組み、ノードの中核、文書の生成と解放を実装する
  - 編集の記録の関数を、追跡が無効なら何もせず、有効ならビットを付けて「子孫の変更」を持つ祖先で止まるまで伝播する形で作り、拡張の設定関数が使う「内容の変更」の通知を公開する
  - ノードをヘッダと型のデータの 1 回の確保で作り、データを 0 で埋めて初期化の関数を呼び、文書の全ノードの環に加え、追跡中なら「新規」を記録する。document 型の生成は拒否する
  - 切り離された部分木を後順に反復で解放する内部関数（型の解放の関数、リテラル、トークン、環からの除去）を作る
  - 型、型の名前、記述子、文書、親・子・兄弟、ブロック/インライン、子を持てるか、包含の判定、関連付けたポインタ、型のデータの取得を実装する
  - 文書を、凍結済みの構文セット（指定がなければ core）で、根を持ち追跡が無効の状態で作り、解放時に環のすべてのノードを解放する。凍結していない構文セットは不正な状態を返す
  - テストで、各組み込みの型の既定の属性とノードの関係の初期値、関連付けたポインタ、切り離したノードを含む全ノードが文書の解放で解放されること（テスト用アロケータのブロック数が 0）、2 つの文書の交互の操作が干渉しないことを確かめられる
  - _Requirements: 1.1, 1.2, 1.3, 1.9, 2.4, 3.1, 3.7, 4.1, 7.4, 7.7, 7.8, 7.9, 7.10, 8.7, 8.12_

- [x] 3.2 ソースの登録・追加と、行と列への変換を実装する
  - ソースを複製して登録し、識別子を 0 から順に返す。長さ 0 と NULL の組み合わせの規則に従う
  - 末尾への追加で既存のバイトの位置を変えず、追加のたびに行の先頭の索引を更新し、チャンクの境目で分かれた CRLF を 1 つの改行として扱う
  - オフセットを 1 から数える行と列（バイト単位）に二分探索で変換し、範囲外を拒否する
  - テストで、LF・CR・CRLF の混在と境目の CRLF を含む入力で行と列が期待どおりになり、追加の前後で同じオフセットのバイトが変わらないことを確かめられる
  - _Requirements: 1.4, 1.5, 3.5_

- [x] 3.3 木の不変条件の検査器と計算量のカウンタを実装する
  - 親子と兄弟のリンクの対称性、包含の規則、「子孫の変更」の祖先への閉包、トークンの整列と範囲、全ノードの環への所属を反復で検査し、違反の理由を返す内部関数を作る
  - 文書に、祖先への伝播の段数とトークンの移動の回数の内部のカウンタを持たせる
  - 内部用のテストで、内部の構造を直接壊した木のそれぞれの違反が理由つきで検出され、正しい木では成功することを確かめられる
  - _Requirements: 4.5, 7.5_

- [x] 3.4 文書による構文セットの所有の受け渡しを実装する
  - 文書が使っている構文セットそのものであり、静的な構文セットでなく、文書がまだ所有していないときだけ所有権を受け取り、どれかに反すれば不正な引数を返して文書を変えない（所有権は呼び出し側に残る）
  - 文書の解放の順を、すべてのノード、ソース、所有する構文セット、文書の構造体の順にする
  - テストで、テスト用アロケータを設定して作った構文セットを渡した文書の解放でブロック数が 0 になること、`deinit` で構文セットを参照する拡張の型のノードを持つ文書の解放がサニタイザの構成で成功すること、静的な core の構文セット・文書が使っていない構文セット・2 回目の受け渡し・NULL の拒否の後も呼び出し側が構文セットを解放できること（二重解放もリークもない）を確かめられる

  - _Depends: 3.1_
  - _Requirements: 1.3, 1.10, 1.11_

- [x] 4. 構文トークンと編集
- [x] 4.1 構造の編集（挿入、移動、置換、切り離し、解放）を実装する
  - 同じ文書、根でないこと、基準の兄弟が親を持つこと、包含の規則（上書きの関数を優先）、子を持つノードのときだけの祖先をたどる循環の検査を、木を変える前にすべて行う
  - 木にあるノードの挿入を移動として扱い、元の親と新しい親に「子の構成の変更」、挿入したノードに「位置の変更」（新規のノードを除く）を記録し、記録を持つ部分木の挿入では追跡の有無にかかわらず祖先へ伝播する
  - 置換、切り離し（根の拒否、切り離し済みは成功）、公開の解放（木にあれば切り離してから部分木を解放、根は何もしない）を実装する
  - 包含の判定と、検査を済ませた切り離しのノードを指定の位置につなぐ処理（記録つき）を、子をまとめた取り込みからも使える内部関数として切り出す
  - テストで、4 つの挿入の位置、移動、置換、拒否のそれぞれで木が変わらないこと、切り離したノードの再挿入、記録の種類と伝播、追跡が無効のときに記録しないことを確かめ、各操作の後に不変条件の検査が成功する

- [x] 4.2 (P) 構文トークンの保持・検査・操作を実装する
  - 種類ごとの検査（改行のバイト、空白のバイト、エスケープの形、文字参照の形、BOM の位置とバイト、遅延継続の長さ 0）、部分的なタブの検査（長さ 1 のタブ、列の数と開始の範囲）、ソースの登録と範囲の検査（桁あふれを含む）、未知の種類と印の拒否を実装する
  - トークンを（ソース、オフセット、タブの列の開始、追加の順）で整列して保ち、順の追加を償却定数時間で行う。取得、削除、同じ文書のノード間での範囲の移動（失敗時はどちらも変えない）、種類の名前を実装する
  - テストで、正しいトークンと不正なトークンの各場合、改行の 3 つの形の区別、接頭辞の印、長さ 0 の遅延継続、1 つのタブを 2 つのトークンに分けた表現、順の保持・削除・移動を確かめられる

- [x] 4.3 リテラルの規則とテキストの一括設定を実装する
  - 文字列の共通の検査（正しい UTF-8、NUL なし）と、改行・空行の判定、LF への正規化と末尾の LF の補完を、属性の設定からも使える内部関数として作る
  - リテラルの方式ごとの規則と型の検査の関数を適用してリテラルを設定し、同じ値なら記録せず、異なれば新しい値を確保してから入れ替えて「内容の変更」を記録する。構文トークンは変えない
  - インラインを持てるノードに、改行で分けた text とソフト改行の列を、新しい子をすべて作ってから既存の子と入れ替える形で設定する
  - テストで、NUL・不正な UTF-8・改行・空行の拒否、複数行のリテラルの正規化、空の code の拒否、同じ値で記録が増えないこと、一括設定の子の並びと記録、設定後もトークンが残ることを確かめられる

- [x] 4.4 組み込みの属性の取得と設定を実装する
  - 見出しのレベル、リストの種類・開始番号・タイト、コードブロックの情報文字列、リンクと画像とリンク参照定義の宛先とタイトル、リンク参照定義のラベルを、設計の表の規則（範囲、改行、空行、ラベルの文字数と括弧と空白の規則）で設定する
  - 型が合わないノードの取得は既定値、設定は不正な引数を返す。同じ値なら記録せず、異なれば「内容の変更」を記録する
  - テストで、各属性の境界値（レベル 0・1・6・7、開始番号 −1・0・999999999・1000000000、999 と 1000 の符号位置のラベル、エスケープした括弧と生の括弧）、型の不一致、記録の有無を確かめられる

  - _Requirements: 2.2, 2.6, 5.1, 5.2, 5.3, 5.4, 5.6, 5.8, 7.1, 7.6_

- [x] 5. トークンを使う機能、複製、走査
- [x] 5.1 (P) ロスレス性の検証を実装する
  - 根から到達できるノードの、指定したソースのトークンを作業領域に集めて整列し、行頭からの列（4 列のタブストップ、1 行目は BOM の後から）を数えながら抜け・重なり・部分的なタブの列の誤りを最初の位置と所有者つきで報告する。不整合は `AMARK_ERROR_NOT_LOSSLESS` で返し、報告の出力引数は NULL でもよい
  - 下流の継ぎ目の代表例（引用の接頭辞と CRLF、遅延継続行、`>\t\tfoo` の部分的なタブ、リストの続きのインデント、BOM、NUL の置換、エスケープと文字参照）を手で組み立てたトークンで表し、すべて成功することを確かめる
  - テストで、意図的な抜け・重なり・タブの列の誤り・切り離したノードのトークンの除外がそれぞれ期待の位置で検出されることを確かめられる
  - _Boundary: TokenCheck_
  - _Depends: 4.2_
  - _Requirements: 6.9_

- [x] 5.2 (P) 複製と別の文書からの取り込みを実装する
  - 部分木を反復で複製し（型のデータは複製の関数、なければバイトの複製）、リテラル・トークン・編集の記録を保ち、関連付けたポインタは複製しない
  - 取り込みでは、取り込み先の構文セットで記述子を対応付け、参照されるソースを取り込み先に複製してトークンのソースの識別子を付け替える。同じ文書なら複製と同じにする
  - 失敗時は作りかけのノードと追加したソースを取り除き、取り込み先を変えない。根の複製と取り込みは拒否する
  - テストで、複製が切り離され、型・属性・リテラル・トークン・子の並びが元と一致すること（参照の関数で比べる）、取り込み元の文書を解放した後も取り込んだノードのトークンのソースを読めること、型を持たない構文セットへの取り込みの拒否、挿入後の「位置の変更」の記録を確かめられる
  - _Boundary: CopyImport_
  - _Depends: 4.1, 4.2, 4.4_
  - _Requirements: 4.6, 4.7, 4.8, 7.3, 8.12_

- [x] 5.5 (P) 子をまとめた取り込みを実装する
  - 挿入の位置が親の子であること、子の部分木のすべての型の対応付け、直接の子のそれぞれの包含の判定を、確保と木の変更の前にすべて行い、違反は不正な引数を返して何も挿入しない
  - すべての子の部分木が参照するソースを重複を除いて集めて 1 回ずつ複製し、子ごとに切り離された複製を作ってから、元の順で指定の位置につなぐ。親に「子の構成の変更」、各複製に「位置の変更」を記録し、複製の記録を祖先へ伝播する
  - 確保の失敗では、作った複製と追加したソースを取り除いて取り込み先を変えない。同じ文書の中ではソースを複製せず、呼び出しの時点の子の並びを写す。子のない取り込み元は何もせず成功する
  - テストで、`before` が NULL と非 NULL のときの子の順と位置、複数の子が同じソースを参照してもソースの数が 1 つだけ増えること、取り込み元の文書を解放した後もトークンのソースを読めること、根を取り込み元にした文書の全体の取り込み、記録の種類、包含に反する子・型のない子・親の子でない `before` の拒否で取り込み先のダンプとソースの数が変わらないことを確かめ、各操作の後に不変条件の検査が成功する
  - _Boundary: CopyImport_
  - _Depends: 5.2_
  - _Requirements: 4.9, 4.10, 4.11, 7.2, 7.3, 7.5_

- [x] 5.3 (P) 走査を実装する
  - 現在のノードとイベントだけを状態に持ち、呼ばれた時点のリンクから次を決める走査を、子を持てる型には入ると出る、葉には入るだけのイベントで、根の外へ出ない形で作る
  - 位置の再設定で、根の部分木に含まれることと葉に出るイベントを指定しないことを確かめる
  - テストで、イベントの並び、走査中の text の変更と子の一括置き換えの後も未訪問の部分を訪問すること、現在のノードの切り離しの後に再設定して続けられること、葉だけの根を確かめられる
  - _Boundary: Iterator_
  - _Requirements: 3.2, 3.3, 3.4_

- [x] 5.4 (P) ノードのソース上の範囲を実装する
  - 部分木を前順にたどり、最初のトークンと同じソースのトークンの最小の開始と最大の終わりを求め、行と列に変換する。トークンがなければ「位置なし」を返す
  - テストで、子孫だけがトークンを持つノード、別のソースのトークンが混ざった部分木、トークンのない新しいノードの結果を確かめられる
  - _Boundary: SourceSpan_
  - _Depends: 4.2_
  - _Requirements: 3.5, 3.6_

- [x] 6. 比較、ダンプ、テスト用の補助
- [x] 6.1 (P) 意味の比較を実装する
  - 2 つの部分木を確保なしに同時に反復でたどり、記述子・型のデータ（比較の関数、なければバイトの比較）・リテラル・子の並びを比べ、トークン・位置・記録・関連付けたポインタを無視する
  - テキストの正規化の指定では、隣り合う text を 2 つのカーソルで連結した文字列として比べ、空の text を無視する
  - テストで、トークンや記録だけが違う木が等しいこと、属性やリテラルの違い、text の分け方だけが違う木が正規化のときだけ等しいこと、別の文書の同じ構造の木が等しいことを確かめられる
  - _Boundary: Equality_

## Implementation Notes
- 1.1: 設計にない内部の名前として、`amark_node_create_with_desc`（tree.h。document.c が根を作るのと、複製・取り込みで使う）、`amark_core_extension` と `AMARK_BUILTIN_TYPE_COUNT`（19u）、識別子で添字にするポインタの配列 `amark_builtin_types[]`（`[0]` は NULL。core の `node_types` は `&amark_builtin_types[1]`）を宣言した。`struct amark_syntax_set` の配列は const の要素を指し、ヒープの構文セットは realloc/free のときにキャストする
- 1.1: `tests/headers/cxx_include_test.cpp` はまだ新しい 6 つのヘッダの関数を呼んでいない（未実装でリンクできないため）。7.5 で各ヘッダの関数の呼び出しを加える
- 2.1: 組み込みの型の `dump` は NULL。組み込みの属性は dump.c（6.2）が、syntax_set.h の型のデータの配置（`amark_builtin_string_t`（NULL は ""）、`amark_list_data_t`、`amark_heading_data_t`、`amark_code_block_data_t`、`amark_link_data_t`、`amark_link_definition_data_t`（先頭が link の配置））を読んで設計の順に書く。attr.c（4.4）も同じ配置を使う
- 2.1: 組み込みの `copy` は `dst_data` を上書きし、失敗時は確保したものを解放してすべての文字列を "" に戻す（その後の `deinit` は安全）。heading（`equal` なし）と list（`copy` なし）はバイトの比較・複製に任せる
- 2.2: 名前の規則 `[a-z0-9][a-z0-9_.-]*` は拡張の型の名前にも適用する。凍結済みの構文セットの凍結は INVALID_STATE。`amark_syntax_slot_entry_t` に整列の第 2 キーの `order` を加えた。静的な core の構文セット（`is_static`）は const のデータだけで、`destroy` は何も書かない。`amark_syntax_set_node_type_of` は線形の探索（定数時間は `amark_syntax_set_desc` だけ）
- 3.1: 包含の規則（`can_contain` の上書きを優先し、なければ `accepts & provides`）は、依存の方向のため node.c の公開の `amark_node_can_contain`（型の識別子）と structure_edit.c の `amark_node_allows_child`（記述子、4.1）の 2 か所に書く。4.1 で、組み込みのすべての型の組と上書きする拡張の型で両者の結果が一致するテストを置く。3.3 の検査器と 5.2/5.5 の取り込みは `amark_node_allows_child` を使う
- 3.1: `amark_document_destroy` は環のノードから根の方向へたどった先の部分木を丸ごと解放する（全体で線形）。解放の順（ノード、ソース、`owned_syntax`、文書）はすでに実装済みで、3.4 は `amark_document_take_syntax_set` を加えるだけでよい
- 3.2: ソースへの追加は、行の索引を先に確保してから `amark_buffer_append` を直接呼ぶ（自分自身のバイトの追加で `amark_buffer_reserve` を先に呼ぶと、realloc で `data` が無効になり use-after-free になる）。CRLF の LF のオフセットは CR の行。CR で終わるソースの末尾のオフセットは、LF が追加されるまで次の行
- 3.3: `amark_node_allows_child` は 3.3 で structure_edit.c に先に実装し、`amark_node_can_contain` と一致するテストは tests/tree/tree_check_test.c（suite allows_child）にある。4.1 では重複して書かない
- 3.3: `amark_tree_check` は「記録を持つノードの親は `DESCENDANTS` を持つ」を検査する。4.1/5.x で、記録を持つ部分木を追跡の有無にかかわらず挿入するときに祖先へ伝播しないと、この検査で失敗する。環への所属は確保なしに件数で照合する
- 4.1: 文書の構造体に内部のカウンタ `stat_cycle_steps`（循環の検査で祖先をたどった段数）を加えた。7.3 は、子を持たないノードの挿入でこれが増えないことで 10.3 を確かめる。親が自分自身になる挿入は、子の有無によらず定数時間で拒否する。追跡が無効のときに作ったノードを、追跡を有効にしてから挿入すると `RELOCATED` が付く（`CREATED` でなければ、の規則のとおり）
- 4.2: `PARTIAL_TAB` を持たないトークンは `tab_column_offset` と `tab_columns` を 0 にしなければならない（違反は INVALID_ARGUMENT。design の TokenStore に追記）。種類の名前は `text`、`marker`、`space`、`line_ending`、`escape`、`char_ref`、`replaced`、`bom`、`lazy_continuation`、未知は `unknown`。`stat_token_moves` は整列した挿入と移動のマージでずらした既存の要素の数。移動で等しいキーは、移したトークンが移動先の既存のトークンの後ろに入る
- 4.3: tree.h の内部関数 `amark_text_check` / `amark_text_has_line_ending` / `amark_text_has_blank_line` / `amark_text_normalize`（空は NULL、CR がなければそのまま複製）/ `amark_text_equal` を attr.c（4.4）で使う。一括設定は各改行（LF、CR、CRLF）を 1 つの softbreak にし、空の text を作らない。空文字列は子をすべて取り除き、子がなく空なら何も記録しない（子の構成が変わらないため）。text の子のリテラルは直接設定し CONTENT を付けない。改行を含むときは softbreak も包含の規則で検査する（この経路と、子を持つノードへの空文字列の CHILDREN の記録は、7.1 の拡張の型のテストで確かめるとよい）
- 4.4: title と label は SPAN のリテラルと同じく LF に揃える（末尾の LF は足さない）。label の「空白」は空白、タブ、LF、CR。符号位置の数は CRLF を 1 つ、エスケープを 2 つと数える。エスケープは ASCII の句読点の前の `\`。末尾の対にならない `\` は拒否する（閉じ括弧をエスケープしてしまうため）。空の label の設定は拒否する。list の start は種類によらず保持・比較し、変われば CONTENT を記録する
- 5.1: ロスレス性の検証の列はバイト単位で数える（`amark_document_position` と同じ。CommonMark では部分的なタブの前に来るのは ASCII のコンテナの接頭辞だけ）。長さ 0 のトークンは集めない。部分的なタブのバイトを通常のトークンが覆うと TAB_COLUMNS。`struct_size` が v1 未満の報告には何も書かない。テストは公開 API だけで書ける（`token_check_test` は INTERNAL でない）
- 5.2: 内部関数 `amark_node_create_copy`（node.c。0 で埋めて `init` を呼ばず、`copy` かバイトの複製でデータを作る。`copy` の失敗では `deinit` を呼ばない）と `amark_document_truncate_sources`（document.c）を tree.h に加えた。複製は記録をそのまま写し、複製自体には `CREATED` を付けない。取り込みは使われるソースだけを識別子の増える順に複製する（トークンの順が保たれる）。copy_import.c の context_init / check_types / mark_sources / copy_sources / copy_subtree / context_rollback は 5.5 で再利用する
- 5.2: 公開の extension.h に、`init` と `copy` は失敗時に自分で確保したものを解放すること、所有するデータを持つ型は `copy` を用意すること（ないとバイトの複製になる）を 7.1 か 7.5 で書き足す。`amark_node_create_copy` は `data_size` が 0 のとき `copy` を呼ばない（init/deinit とは非対称。必要なら直す）
- 5.5: copy_import.c の context_init は確保しない初期化と `context_alloc_source_map` に分けた。型の検査が確保より先になったので、`amark_node_copy` / `amark_node_import` でも型の拒否は OOM より INVALID_ARGUMENT が優先される。子をまとめた取り込みは、複製をすべて作ってから（スナップショット）`amark_node_link_child` でつなぐ
- 5.3: 走査は最初の `next` の前はノード NULL・イベント NONE、DONE のときノード NULL。`amark_iter_next(NULL)` は DONE。`reset` は ENTER と EXIT だけを受け付け、開始前と DONE の後でも使える。葉は `amark_node_can_have_children` が偽のノード。オブジェクトのポインタを返す出力引数は、失敗時に NULL にする（foundation の規約。`amark_iter_create` も同じ）
- 5.4: ソース上の範囲では、長さ 0 のトークン（遅延継続行）も位置として数える（5.1 のロスレス性の検証とは異なる）。単独なら幅 0 の範囲になり、他のトークンの範囲を広げることもある。false のとき（トークンなし、NULL、`struct_size` が v1 未満）は `out_span` に何も書かない。ノードの中のトークンはソースの順なので、「最初のトークン」はそのノードで識別子が最小のソースのもの
- 6.1: `amark_node_equal` は a か b が NULL なら false（両方 NULL でも）、未知の印は無視する。`equal` は `data_size` が 0 でも呼ぶ。正規化は text の兄弟の並びだけをつなぎ、他のノードや段をまたがない。テストに不足：正規化で text と同じリテラルの code を比べるケース、`data_size` 0 で `equal` を持つ型のケース（7.1 で足すとよい）
- 6.2: ダンプの記号は属性名と同じ文法 `[a-z][a-z0-9_]*`（6.3 の読み手も合わせる）。`:tokens` はトークンのリストのリスト、`:tab` は partial_tab のときだけ、`:span` は範囲があるときだけ。リテラルの方式を持つ型は空でもリテラルを出す（`(text "")`）。書き手は最初の失敗を保持し、拡張の `dump` が無視しても `amark_node_dump` はその失敗を返す。未知の印は無視する
- 6.2: `AMARK_DUMP_SPANS` はノードごとに `amark_node_source_span` を呼ぶため、計算量は部分木の大きさの和（≒ 字下げを含む出力の大きさ）にトークン数を掛けたもの。設計の「ダンプは出力の大きさに線形」は span の指定がないときのこと。テストとデバッグ用として許容する。equal_dump_test は未知の記録のビットを設定するため INTERNAL
- 6.3: 組み立ての誤りの理由は stdlib の malloc で確保し `amark_test_tree_free_reason` で解放する（Amark のアロケータを使わないので OOM の掃引に影響しない）。`amark_test_tree_print_mismatch` を補助に加えた。attr_fn には文字列は復号して、それ以外の値は入力の文字列のまま、NUL 終端で渡す。空の文字列・リテラルは設定しない（新しいノードのダンプを読み戻せるように）。`(document ...)` の失敗では追加した子を解放し、根のトークンを保存した列に戻す（根への attr_fn の変更は戻さない）。成功時の `:tokens` は根の既存のトークンに加わる。テストは公開用と INTERNAL 用の 2 回登録して両方とリンクできることを確かめる
- 7.1: `amark_node_create_copy` は `copy` があれば `data_size` が 0 でも NULL のデータで呼ぶ（init / deinit / equal / dump と同じ。5.2 の非対称は解消）。extension.h に、NULL のデータでの呼び出し、所有するデータを持つ型は `deinit` と `copy` を用意すること、`init` と `copy` は失敗時に自分で解放すること（`deinit` は呼ばれない）、`deinit` は `init` か `copy` が作ったノードごとに 1 回であることを書いた。4.3 と 6.1 で残したテストの不足は extension_type_test.c と equal_dump_test.c で埋めた
- 7.2: tests/tree/oom_test.c は表駆動（prepare / run / failed_cleanly / succeeded）で、各ケースで操作の中の確保が少なくとも 1 回失敗したこと（`op_failures > 0`）を確かめる。そのため prepare でトークンと構文セットの配列の容量を埋める（INTERNAL の `token_capacity` と `extension_capacity` を読む）。確保しない属性の設定は対象外
- 7.3: 深い鎖は下から組み立てる（切り離した block_quote が下の鎖を受け取る）。上から組み立てると、循環の検査が壊れたときに組み立て自体が二次になり、テストが失敗せずに長時間かかる。計算量のループは、祖先をたどった最初の編集で打ち切る
- 7.4: ファジングターゲットは foundation の命名に合わせて `amark_add_fuzzer(tree_edit_fuzz ...)`（design の Modified Files も直した。テスト名は `fuzz.tree_edit.corpus`）。ハンドルのバイトは個数を法とした添字で 0xff が NULL。種はレビューの深さ 3 の伝播の種（deep_propagation）を含む 10 個。`amark_document_check_tokens` は NOT_LOSSLESS のときだけ報告に問題を書く
- 7.5: gcc の Release（-O3 -Werror）で -Wmaybe-uninitialized の誤検知が 3 か所出たので初期化した（copy_import.c の `bytes`、tree_builder.c の `number`、extension_type_test.c の NAOS_REQUIRE_NOT_NULL）。後続の spec も Release の構成でビルドを確かめる。cxx_include_test は 6 つの新しいヘッダの関数を呼ぶ（1.1 の残りは解消）。エクスポートは AMARK_API の 128 関数と両方向で一致する（宣言したのに定義のない公開関数の検出は自動化していない）
- 検証（validate-impl 1 回目）: 祖先への `DESCENDANTS` の伝播を edit_tracking.c の内部関数 `amark_edit_propagate_descendants` 1 か所にまとめた（structure_edit.c の重複を除いた）。ソースへの追加の後のトークン（1.5）と `amark_syntax_set_insert_before` の確保失敗（1.8）のテストを足した。Implementation Notes の決定を design.md の各節に反映した
