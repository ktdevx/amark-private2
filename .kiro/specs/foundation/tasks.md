- [x] 1.2 版の唯一の定義と、それを読む CMake の仕組みを作る

  - CMake からヘッダを読み、版、動的ライブラリの互換性番号（1.0 未満は「0.マイナー」、以降はメジャー）、パッケージの互換性の方式を決める仕組みを作る

  - ヘッダの版の数の書式を意図的に崩す（例：先頭に 0 を付ける）と構成が失敗し、元に戻すと版が CMake の変数として読めることを確認できる

- [x] 1.3 コンパイラの設定を Amark のターゲットに適用する仕組みを作る

  - シンボルの可視性を既定で hidden にする
  - サニタイザの指定（address、undefined）を最上位のときだけ全体に適用し、未知の値や未対応のコンパイラでは構成を失敗させる
  - 未使用の変数を含む試しのソースが、最上位の構成ではエラー、警告をエラーにしない指定では警告だけになることを確認できる
  - _Requirements: 1.2, 1.4, 1.5, 1.6, 5.2_

  - 全体をまとめるヘッダを作り、エクスポートと版のヘッダを include する。以降の各タスクは、自分の公開ヘッダを設計の正規の include の順（PublicHeaders）でここに加える
  - テストかファジングを作るときだけ、同じオブジェクトから内部テスト用の静的ライブラリを作り、テストを作るときはライブラリの出力先をテストと同じディレクトリにする

- [x] 2.2 差し替え可能なグローバルのアロケータを実装する
  - 標準ライブラリと同じ形の確保・0 で初期化する確保・再確保・解放のコールバックだけを持つ、レイアウトを固定した公開の構造体と、標準ライブラリに基づく既定のアロケータを用意する
  - グローバルのアロケータを設定する関数（コールバックの欠落を拒否して設定を変えない、値でコピーする、NULL で既定に戻す）と、桁あふれを検出する加算と乗算の内部の関数を作る
  - 確保・0 で初期化する確保・再確保・解放の公開の関数を作る。サイズや要素数が 0 の確保はコールバックを呼ばずに NULL を返し、NULL でないブロックのサイズ 0 への再確保は解放して NULL を返す。コールバックに 0 や NULL を渡さない。0 で初期化する確保の桁あふれではコールバックを呼ばない
  - 公開ヘッダをまとめのヘッダに加える
  - 設定を変えてよい条件と、コールバックのスレッド安全の要求、0 の確保が返す NULL は失敗でないことを公開ヘッダに書く
  - 記録するアロケータを設定したテストで、確保・0 で初期化する確保・再確保・解放が設定したアロケータを通ること、0 で初期化する確保の領域の全バイトが 0 であること、NULL の設定で既定に戻ること、不完全なアロケータが不正な引数になり設定が変わらないこと、桁あふれでコールバックが呼ばれないこと、0 の確保がコールバックを呼ばずに NULL を返すこと、サイズ 0 への再確保が解放だけを呼んで NULL を返すことを確かめられる

- [x] 2.3 テスト用アロケータと確保失敗の総当たりの補助を作る

  - 各ブロックに目印とサイズを記録し、見知らぬポインタの解放や二重解放をテストの失敗として報告する

  - わざとリークする処理と、メモリ不足以外を返す処理に対して補助が失敗を報告し、正しい処理に対しては成功することを確かめるテストが通る

  - 公開ヘッダをまとめのヘッダに加える（2.5 はまとめのヘッダに触れないため並行できる）

## Implementation Notes
- 1.2: 版の読み取りは `cmake/AmarkVersion.cmake` の `amark_read_version(<header>)`。出力は `AMARK_VERSION{,_MAJOR,_MINOR,_PATCH}`、`AMARK_SOVERSION`、`AMARK_PACKAGE_COMPATIBILITY`（SameMinorVersion/SameMajorVersion）。後続（1.4、3.3）はこの名前を使う
- 1.2: `version.h` の `amark_version_number`/`amark_version_string` の宣言、`export.h` の include、宣言の囲みは 1.4 で追加する
- 1.2: 設計どおりの `(long)` キャストのため、`AMARK_VERSION_NUMBER` は `#if` では使えない（C の定数式としては使える）。設計の改訂の要否は人の判断に委ねる
- 1.3: `cmake/AmarkCompilerOptions.cmake` は `project()` とオプションの宣言の後、ターゲットを作る前に include する（サニタイザはディレクトリ単位で、include 以降のターゲットにだけ効く）。ターゲットには `amark_target_defaults(<target>)` を呼ぶ
- 1.3: このコンテナの clang にはサニタイザのランタイムがない。サニタイザの成功経路は gcc で確かめる
- 1.4: 最上位の CMakeLists.txt の `include(AmarkTesting OPTIONAL)` と `if(EXISTS tests/CMakeLists.txt)` の囲みは暫定。1.5 で外す。`include(AmarkFuzz OPTIONAL)` と `if(EXISTS fuzz/CMakeLists.txt)` は 3.5 で外す。この目的に限り、1.5 と 3.5 は最上位の CMakeLists.txt を編集してよい
- 1.4: ターゲットは `amark_objects`（OBJECT、`amark_target_defaults` を適用）、`amark`、`Amark::amark`、`amark_internal`（テストかファジングのときだけ、include/ と src/ を PUBLIC に持つ）。テストを作るときの実行時の出力先は `${PROJECT_BINARY_DIR}/bin`
- 1.5: テストは `amark_add_test(<target> SOURCES … [INTERNAL] [LIBRARIES …] [LABELS …])` で登録し、各テストは CTest に `<target>.<suite>.<test>` として載る。`amark_test_support` は今は INTERFACE ライブラリ（tests/support と Naos::naos）。2.3 で test_allocator.c を加えるときに STATIC に変える
- 2.3: 確保失敗の総当たりは `AMARK_CHECK_OOM_SWEEP(scenario, ctx)`（tests/support/test_allocator.h）。結果の構造体に設計にない `truncated` を加えた。総当たりの中で `NAOS_FAIL` が起きると既定のアロケータに戻らないので、テストの teardown で `amark_allocator_set(NULL)` を呼ぶ
- 2.5: `src/base/unicode_tables.inc` は `amark_unicode_range_t` を定義しない。2.6 の unicode.c は `<stdint.h>` と `typedef struct { uint32_t first; uint32_t last; } amark_unicode_range_t;` を include より前に置く。生成スクリプトは `include/amark/unicode.h` がないと版の照合を警告で飛ばすので、2.6 でヘッダを加えたらエラーに変える（この目的に限り 2.6 は tools/gen_unicode_tables.py を編集してよい）
- 3.1: データ駆動のテストは `amark_add_generated_tests(<target> GENERATOR <script> DATA <files…> …)`。生成スクリプトは先頭で `cmake_minimum_required(VERSION 3.21)` を呼び、`include(AmarkTestGen)` の補助を使う。Makefiles では生成物（`.c`）を手で消したら `.stamp` も消す。スイート名の識別子への変換は AmarkTesting.cmake と AmarkTestGen.cmake の 2 か所にあるので、変えるときは両方を直す
- 3.3: パッケージは `lib/cmake/Amark/`（AmarkConfig、AmarkConfigVersion、AmarkTargets）、`lib/pkgconfig/amark.pc`、`share/licenses/amark/LICENSE`。必須のコンポーネントが一致しないときの理由のメッセージは「the requested kind of Amark (components: …) is not installed in <prefix> … the installed kind is "static"」で、3.4 はこれを照合できる
- 3.5: ファジングターゲットは `amark_add_fuzzer(<name> SOURCES … CORPUS <dir> [LIBRARIES …])`。再生のテスト名は末尾の `_fuzz` を除いた `fuzz.<name>.corpus`（ラベル fuzz）。空のコーパスは構成時のエラー。libFuzzer の実行はこのコンテナでは確かめられない（compiler-rt がない）ので、CI のファジングのジョブで確かめる
- 4.1: 公開の名前の接頭辞と amark.h の include の順は `lint.public_headers`（cmake/scripts/check_public_headers.cmake、ラベル lint）で検査する。正規の順の一覧は design の PublicHeaders の表とこのスクリプトの 2 か所にあるので、後続の spec が公開ヘッダを加えるときは両方を直す
