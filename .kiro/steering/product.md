# Product Overview

Amark は、Markdown テキストと構文木を相互変換する C99 ライブラリである。CommonMark に完全準拠したパース、構文木の参照と編集、HTML へのレンダリング、Markdown への書き戻しを、1 つの一貫したモデルの上で提供する。方言（GFM など）は、利用者が公開の拡張 API で構文を組み合わせて表現する。

対象とする利用者は、C/C++ のアプリケーションやツールに Markdown 処理を組み込む開発者である。他言語のバインディングの土台になることも想定する。

## Core Capabilities

- **パース**：Markdown を、意味を表す構文木（AST）に変換する。CommonMark spec に 100% 準拠する。
- **ロスレスな往復**：各ノードは元の表記を保持する。無編集で書き戻すと、入力とバイト単位で同じ Markdown になる。
- **木の編集**：ノードの挿入・削除・移動・置換やテキストの変更ができる。書き戻すと、編集した部分は、編集後の木と同じ意味の正しい Markdown として出力され、それ以外は元の表記のまま残る。
- **レンダリング**：HTML（CommonMark 互換、安全モードあり）と Markdown の 2 系統を持つ。
- **拡張**：公開の構文定義 API で、ブロック、インライン、後処理、レンダラの出力を定義できる。CommonMark 自体もこの API の上で「組み込み拡張」として実装している。

## Target Use Cases

- **翻訳やローカライズ**：Markdown 文書のテキスト部分だけを置換する。書式や表記は保ったまま書き戻す。
- **文書処理ツール**：リンクの書き換え、見出しの抽出、目次の生成、Lint などの静的解析。
- **Markdown を HTML に変換する組み込み処理**：CMS、静的サイトジェネレータ、ドキュメントツール。
- **独自の方言の実装**：GFM 相当や、自社の記法を、拡張の組み合わせで実装する。

## Value Proposition

- **往復で表記が変わらない**：一般的な AST ライブラリ（cmark など）は、書き戻すと表記が正規化されてしまう。Amark は、触っていない部分の差分を出さない。編集を前提としたツールに向いている。
- **方言は拡張で完全に表現できる**：中核の構文も、利用者と同じ拡張 API を使っている。そのため、拡張 API の表現力が中核の構文と同じであることが構造的に保証される。GFM 相当（表、取り消し線、タスクリスト、拡張オートリンク、タグフィルタ、脚注）を、配布物に含めずに拡張だけで実装できることを、テストで検証している。
- **移植性**：C99 だけで書き、外部のランタイム依存を持たない。Windows、Linux、macOS で、静的ライブラリと動的ライブラリの両方を提供する。
- **ライセンス**：MIT（Copyright (c) The Amark Authors）。

## Non-Goals

- GFM などの方言を、配布物として同梱すること
- CLI ツール、他言語のバインディング（将来の候補）
- フォーマッタとしての整形（無編集の部分を書き換えること）。将来、オプションとして追加する余地は残す。
